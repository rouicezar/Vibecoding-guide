# 逐项检查记录

三轮分别核对：① 原步骤与最终提示词；② 全栈示例交接和异常路径；③ 渲染、提示词操作与参考程序验证。下表为编辑核对，不表示逐条交给外部 AI 执行或学员已完成。

| 动作 | 本轮检查与补齐 |
|---|---|
| idea | 先用自己的话写：我想每天记下学了什么，关闭网页、重启电脑后还能看到。跟练项目只给自己在本机使用。 核对：你能说清“写一条、保存、再次找到”，而不是只说做一个漂亮网页。 |
| description | 把前一步想法整理进模板；在“通过条件”写明：换一个浏览器打开同一服务仍能读到记录。 核对：项目描述明确有页面、后端和数据库；本机使用不等于只存在浏览器里。 |
| tool | 在 Codex 中选择能关联本机文件夹的项目。先看下面定位图：项目、对话、文件预览分别做什么。 核对：能在项目对话让 Codex 检查文件并报告实际路径。 |
| folder | 在文稿里新建 learning-journal 文件夹。它是练习项目，不是本网站的源码目录。 核对：知道完整位置，里面没有别人的项目。 |
| open-project | 打开刚建的项目文件夹，在其中新建对话，发送只读路径检查。 核对：回复路径与自己建立的文件夹一致。 |
| checkpoint | 把全栈练习的已确认描述交给 Codex，保存 idea.md 和起点版本。 核对：idea.md 包含后端数据库保存要求，Git 版本可以指出。 |
| first-file | 点击 Codex 回复中的 idea.md 文件链接，或在原项目文件夹打开它，核对正文。 核对：能在文件正文找到“后端数据库”和本机使用范围。 |
| clarify | 逐个回答：谁使用、是否公开、记录哪些字段、保存后如何找回。跟练先选本机单人。 核对：已确定标题、内容、时间；明确不需要登录和跨设备联网。 |
| scope | 确认只做新增记录和历史列表；一条记录含标题、内容、创建时间。 核对：列表、新增、保存失败提示和重新读取都有通过条件。 |
| requirements | 逐项核对标题 1–80 字、内容 1–2000 字；前后空格不算有效内容。保存成功后才清空输入。 核对：服务不可用时原输入保留；后端独立拒绝空白和超长内容。 |
| stories | 用一句完整场景串起来：晚上打开网页，写今天学到的事，保存，第二天再次打开查到。 核对：docs/stories.md 同时覆盖正常保存与保存失败后重试。 |
| prototype | 只看输入框、保存按钮、状态提示和历史列表的位置；用明显标记的模拟记录试顺序。 核对：能说出保存前、提交中、成功、失败四种画面；原型还没有真实数据库。 |
| choose-stack | 认识三部分：浏览器里的 HTML/CSS/JavaScript 是页面；Python Flask 接收请求；SQLite 把记录放在电脑文件里。 核对：docs/design.md 写出每部分做什么、文件放哪、如何一起启动。 |
| plan | 任务表分成环境、页面、数据库建表、后端接口、页面接线、失败处理、重启和验收；一次执行一项。 核对：每项有文件、依赖和亲手检查方法，保存功能明确在哪一项完成。 |
| environment | 在 Codex 项目对话发送环境提示词；让它检查 Python，再创建本项目 .venv（单独放依赖的文件夹）并安装确认过的 Flask。 核对：最小服务打开真实 http 地址；README 有所在目录、启动命令和停止方式。 |
| preview | 让 Codex 只做第一项页面任务，点击回复里的实际 http 网址。此时能看见输入框和列表占位，不要求保存成功。 核对：浏览器地址以 http 开头；页面明确未接数据库，不显示假的保存成功。 |
| interface | 对照原型核对标题、内容、按钮和提示是否看得懂；手机窄屏也能填写。 核对：输入框有名字；保存按钮和结果提示可见，文字不被截断。 |
| save | 按下面四个小检查逐项让 Codex 执行：建表、接口、页面接线、读回。每项看到真实结果再继续。 核对：输入“练习 A”保存后有真实记录编号；第二浏览器访问同一服务也能读到。 |
| flow | 从页面输入“练习 B”，点一次保存，看成功提示与列表，再刷新和换浏览器读同一编号。 核对：页面、接口和数据库三处的记录编号及内容一致。 |
| test | 分别试空白、全空格、超长、连续点击；再由 Codex 停止本练习服务后试保存，确认原文还在。 核对：无效内容不入库；服务停了不能提示成功；连点同一次提交只新增一条。 |
| restart | 记下练习记录编号，按 README 停止服务，再从原文件夹重启并打开网址。 核对：同一编号仍可读取；重启没有重新创建空库。 |
| accept | 按原需求亲手做一轮新记录、重新读取、失败后重试和重启检查，再填写自己的实际结果。 核对：验收记录对应当前版本，明确前端、后端、数据库各有什么证据。 |
| feedback | 把失败时输入的测试内容、点击顺序、时间、页面提示和报错放在一起；截图不要含私人资料。 核对：别人能照记录复现，不只有“保存坏了”。 |
| repair-plan | 让 Codex 先复现，再说明只改哪一层，改完重跑哪条失败操作。 核对：修复计划包括数据保护及原本正常保存的回归检查。 |
| repair | 执行确认过的一项修复，自己重做原失败操作，再确认旧记录还在。 核对：原问题通过，正常新增/读取及已有数据也通过。 |
| delivery | 本轮先选本机自用：一个启动方法、一个网页入口、一份数据库。公开给别人用是之后的单独决定。 核对：知道 localhost 只指向打开它的那台电脑；完整全栈项目可先本机交付。 |
| release-review | 核对当前版本确实通过保存、读回、异常和重启；确认启动说明没有只写“打开 HTML”。 核对：清单涵盖依赖、启动、数据库位置、备份和未验证事项。 |
| package | 让 Codex 准备启动说明和依赖文件，在独立测试副本试运行；数据库用测试数据，不复制私人记录。 核对：从干净副本可以启动前后端、保存并读回一条记录。 |
| live-check | 从交付说明的入口亲手打开，新增“交付核对”并重启读回，不使用旧页面缓存当证据。 核对：实际交付版本可用，数据库路径和使用范围写清楚。 |
| publish | 这个动作是静态网站的可选参考。本全栈练习直接继续维护，不把 Python 和数据库上传 Pages。 核对：明确 Pages 不能运行本练习后端，数据库不公开。 |
| maintain | 按 README 备份数据库，在独立临时目录恢复并核对同一记录；下次先读交接文件再继续。 核对：备份文件实际能恢复，原数据库未被覆盖。 |

## 第二轮发现并修正
- prototype 主体读取用户故事的位置仍写 requirements，与独立 stories 文件不一致；修正最终提示词。
- preview 原先要求本步循环所有任务，容易与后续 interface/save 重复；改为按任务归属执行，已完成项只复核。
- 全栈补充若要求学员自己拼接，容易漏原先文件前提；改为可一键生成的完整合并提示词，提醒不重复发送通用模板。
- 填写表与验收不能变成 AI 代填：填写类只显示填写方向，保留真实路径、版本、结论由本人填写。
- 网络返回失败不能证明数据库未写入：补上恢复后先读列表再重试，避免重复提交。
- Pages 静态部署与 Flask 后端冲突：本例明确跳过可选 Pages，先完成本机交付。

## 第三轮边界
- 自动化检查双语覆盖全部 31 动作，浏览器检查代表性保存动作模板和页面。
- 参考程序真实运行验证不等于逐个提示词交由外部 AI 生成完整项目，也不等于独立学员已完成。
- Codex 原生界面访问被工具明确禁止；仅完成带标注的定位示意，真实入口截图仍待可用素材。
