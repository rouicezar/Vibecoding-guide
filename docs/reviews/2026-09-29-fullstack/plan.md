# 零基础全栈跟练：要求、设计与多轮检查

> 当前边界以 [产品需求](../../product-requirements.md) 为准。本文中的固定数量与旧阶段限制仅作历史记录，不约束后续教学拆分与补全。

用户目标：长期以零基础教学顾问视角，逐项检查每个动作和提示词，补入口图片、前后端与数据库开发、常见问题和处理方法。保留六阶段、18 节点、31 动作。

## 本轮设计

以“个人学习记录”为贯穿示例：网页填写和列表是前端；接收与检查请求的是后端；SQLite 文件是数据库。先完成本机单人版，不引入账号、支付和云服务。新练习采用 HTML/CSS/JavaScript + Python Flask + SQLite；已有项目沿用确认方案，不能强制重建。示例不是网站本身，指南仍为静态 Astro。

每个现有动作增补同一跟练项目的具体操作、可见产物、卡点恢复和适用的提示词补充。通用提示词仍适合用户自有项目；全栈跟练明确标注补充文本如何与该步骤模板一起发送。填写类步骤继续由本人填写，不能生成虚假的验收结果。

按三轮记录：①逐项核对最终渲染数据和提示词，定位断层；②核对同一项目文档、前端、后端、数据库的交接和失败路径；③技术验证、页面阅读、示例实际运行及回归。验证状态明确区分静态核对、示例执行、学员试用。

## 关键缺口

- 当前通用路线支持多类项目，但没有贯穿所有步骤的确定全栈示例；单纯刷新页面不足以证明后端和数据库已实现。
- preview 让学员重复执行所有任务，后续 interface/save 又容易被误解为重复开发；须明确对应任务在这些步骤完成，不二次实现。
- prototype 最终提示词仍将用户故事描述为 requirements 内容，应统一读取独立 stories 文档。
- 服务启动、端口、请求、数据库路径、建表、后端校验、重复点击、连接失败、重启和备份恢复需要具体可观察的方法。
- 现有图为抽象流程图，不能证明学员能找到 Codex 入口。

## 图片约束

计算机工具明确禁止访问 Codex 原生应用，不能改用其他截图途径绕过。优先检查官方公开界面素材，标明来源；素材不足时只制作明确标注的定位示意，不能冒充当前真实截图。真实入口截图仍需后续可用素材，不将此项冒报完成。

## 验收

保留规模与九槽位结构；覆盖 31 动作及双语；提示词不跳阶段；前后端数据库闭环与重启持久化、空白校验、服务停止、备份恢复有实测证据；所有原有验证通过。图片缺口如仍存在需明确报告。
