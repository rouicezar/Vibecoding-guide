## 1. 做了什么

把路线图上的 **18 个关键节点** 从「点击后跳到某一个教学动作」改成「进入本节点自己的页面」；节点页由**一个模板**渲染，页头字段与步骤内的槽位顺序在所有节点、所有步骤中完全一致。

### 改动前

| 问题 | 现象 |
| --- | --- |
| 点节点只看到其中一个动作 | 点节点 12 → `/learn/preview`（1 个动作），但它实际有 4 个动作 |
| 不知道本节点有几个步骤 | 全站没有任何地方显示 |
| 开始做事要跳两次 | `/roadmap/<节点>`（补充知识）→ 再点「带着做」→ `/learn/<动作>` |
| 每个动作一个独立页面 | 靠页脚「已核对，下一步 →」线性推进，看不到全貌 |
| 同一阶段两个名字 | 路线图写「制作并验证功能」，学习页写「按计划开发，实现功能」 |

### 改动后

- `/node/<id>`：18 个节点页（中英各 18，共 36 页）。
- 页头固定 5 项：阶段徽标、节点序号 `M / 18`、H1 名称、一句话白话、为什么要有这一节点；再加两个固定字段「本节点步骤数」「做完你会得到」。
- 步骤用原生 `<details>` 折叠，展开后是**固定 9 个槽位、固定顺序**。
- 路线图上的 18 个节点改为指向 `/node/<id>`。
- 阶段名称统一由 `src/data/nodes.ts` 的 `nodePhases` 提供，路线图与节点页共用一个来源。

## 2. 固定的 9 个槽位（步骤展开后）

顺序与标题在 28 个线性步骤 + 3 个修复步骤中完全一致。这是「培养用户习惯」的落点：用户第二次打开任何一个步骤，都知道第几段讲什么。

| # | 槽位 | 数据来源 |
| --- | --- | --- |
| 01 | 开始前带上，做完交给下一步 | `stepSupport.input` / `.output` |
| 02 | 这一步要达成 | `lesson.understanding.why`（回退 `stepSupport.answer`） |
| 03 | 你要做的 | `lesson.where` + `lesson.actions[]` |
| 04 | 不会具体操作？逐项跟着做 | `stepSupport.steps[]` |
| 05 | 这一步出现的词 | `stepSupport.terms[]` → `glossary` |
| 06 | 可能卡住的地方 | `lesson.issues[]`（先看哪里 / 这样处理 / 恢复后应该看到）+ 该步全部问题页入口 |
| 07 | 发给 AI 的话（可一键复制） | `lesson.prompt` → `PromptTemplate` |
| 08 | 看到这个结果才算完成 | `lesson.expected` |
| 09 | 没有出现预期结果时 | `stepSupport.recovery` + `stepSupport.example` |

步骤页脚固定两个出口：「卡住了，先解决这一件事 →」`/learn/<step>/help`、「记录并核对这一步 →」`/learn/<step>`（进度与记录逻辑仍由既有 `learning.ts` 脚本负责，未改动）。

## 3. 18 节点 → 31 步骤归位

`src/data/nodes.ts` 是唯一数据源。28 个线性步骤 + 3 个修复步骤 = 全部 31 个教学动作，不重复不遗漏。

| 阶段 | 节点（步骤数） |

| 1 把想法说清楚 | idea(1)、description(1) |

| 4 制作并验证功能 | checkpoint(1)、environment(1)、preview(4) |


新增的 `verify-nodes.mjs` 承担 7 组断言：

1. 18 个节点、编号 1..18 连续、阶段合法、中英文字段齐备、每节点 1–5 个步骤
2. 28 + 3 = 31 覆盖全部教学动作，无重复、无遗漏
3. 9 个槽位的数据在每个步骤中齐备（`idea` 的提示词槽位由页面给出替代说明）
4. 术语引用全部存在于词库（槽位 05 无死链）
5. 旧节点映射指向真实节点
6. **18 个节点页必须出现同一组 9 个槽位标题，且顺序相同**；页头 7 项齐备；`节点 M / 18` 与 `共 N 个步骤` 必须出现
7. 路线图上的 18 个节点必须指向 `/node/<id>`

第 6 条是「不能每个步骤都不一样」的机器保证：以后任何人调整某个节点的模板，校验会立刻失败。
