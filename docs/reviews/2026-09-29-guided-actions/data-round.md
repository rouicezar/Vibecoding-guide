# 前后端、数据库与排障内容细化

## 需求与设计

沿用当前产品需求及用户明确边界：保持布局、UI、逻辑结构。直接细化 interface、save、repair-plan、repair 的既有步骤和结果检查；补充现有全栈示例中的白话提示词和报错处理。不得把示例应用开发当作教学完善，不新增顶层节点。

操作链：定位前端输入与结果 → 核对后端和数据库 → 准备表 → 验证保存读取接口 → 页面连接 → 跨浏览器与重启读回 → 留证据 → 复现问题 → 只读定位 → 审阅修复计划 → 修复与本人复测。

每项写明位置、动作、即时提醒、预期和恢复。通用步骤允许用户使用自己的项目；SQLite 和学习记录字段仅属于既有跟练示例。工具测试与学员验收分别记录。

## 验证与剩余项

类型检查 0 错误、0 警告（8 条既有提示），构建与全部 15 项验证通过。此轮细化 4 个环节共 16 个具体操作，累计逐项核对 11 个环节、42 个操作。新增 3 类保存排障，补充数据库与只读诊断提示词。此轮不声明真实学员已独立完成；真实工具入口截图仍待可用素材，不用虚构界面补齐。

## 用户追加的样式修复

用户提供两张截图，明确授权本轮修正同类问题：编辑框与按钮贴边、实色主按钮文字变暗。检查全部五种 textarea 组件和共享主按钮样式；在现有 palette.css 统一直接相邻编辑框的按钮间距，主按钮及文字子元素保持白色，普通文字链接悬停规则排除主按钮。不改页面结构和行为。
