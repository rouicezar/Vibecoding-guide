# 五项目标与测试机制

目标：零基础用户沿现有网站完成作品的测试、备份恢复、交付使用，并能找到工具入口和连续使用提示词。继承当前产品需求，不改布局、导航、进度或交互结构，不自动发布。

| 目标 | 内容交付 | 通过条件 | 验证方式 |
|---|---|---|---|
| G1 全流程测试 | 正常、异常、重启的逐操作指导和记录模板 | 从准备到结果再到失败反馈都有入口；不能以 AI 自报代替本人检查 | 双语内容逐项检查；隔离参考程序 HTTP/数据库检查；浏览器亲走保存/失败 |
| G2 备份与恢复 | 代码、数据库、本站草稿的区别；独立副本恢复与检查 | 明确来源、备份位置、恢复位置、停止条件；原库不受影响 | 隔离备份/恢复运行，原库记录比较；提示词保护原库约束 |
| G3 交付与使用 | 本机与公开使用选择；前端/后端/数据库运行及接收者操作 | 交付前置条件和目标环境测试明确；不把源码或静态托管当完整动态服务 | 本机独立启动与读回；公开分支内容核对，未真实部署不标实测 |
| G4 入口图片 | 有来源的真实工具界面配白话定位说明 | 图片能支持对应操作，来源/语言/核验日期明确，生成图不冒充截图 | 优先可用真实官方截图；逐张视觉核对；网站图片渲染与链接检查 |
| G5 提示词衔接 | 所有现有步骤的前置文件、产物、下一步去向与缺项恢复检查 | 后一步不能突然要求无生产者的文件；模板区别填写资料/工具执行 | 全部步骤双语及文件依赖审计；修复重复/残缺表达；模板验证 |

执行顺序：需求和本计划 → 原有内容内细化 → 内容一致性检查 → 网站 check/build/verify → 隔离运行与浏览器核验 → 更新结果和任务记录 → 仅提交本任务文件。

失败机制：发现内容断层先修当前链路；技术失败定位后重验受影响检查；图片权限限制使用独立公开官方素材，无法取得真实素材就明确未达成，绝不伪称完成。用户可用性证据分为编辑核对、参考运行、浏览器跟做和真实学员试用，最后一项没有执行不得宣称。
