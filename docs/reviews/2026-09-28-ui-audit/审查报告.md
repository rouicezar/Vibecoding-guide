# UI 审计：可优化空间

日期：2026-09-28。基线：`rouice/beginner-learning-redesign`（f5ebf9a，已部署）。
方法：**构建产物度量 + 全站 CSS 统计 + 渲染 HTML 结构分析 + 项目内 39 张评审截图目视**。

> **证据边界**：本环境无法启动 headless Chrome（进程挂死），因此**没有本轮实时截图**。项目内的 39 张评审截图均为改动前（2026-09-26/27）拍摄，且**全部是 JPEG 伪装成 `.png`**。凡涉及"看起来怎样"的判断都标注为基于这些旧截图；凡涉及尺寸、字号、对比度、体积、结构的判断都来自本次实测，可复现。

## 1. P0：三件收益最大、风险最低的事

### 1.1 品牌图 492KB——占单页体积 61%

| 文件 | 尺寸 | 字节 |
| --- | --- | --- |
| `public/brand/vibe-guide-mark.png` | **1254×1254 RGBA** | **492,631** |
| `dist/_astro/*.css` | — | 125,406 |
| `dist/zh-cn/node/preview/index.html` | — | 182,084 |

`node/preview` 未压缩总量 800KB，**品牌图占 61%**；gzip 后 HTML+CSS 压到 34KB，但 **PNG 压不动**，所以实际传输里它占 **92%**。

它被用在两处：页头 36×36 的 `<img>`（`alt=""`，正确）和 favicon。**展示 36px，下载 1254px。**

**这一条我在前三份报告里都提过，至今未修。** 它是全站单点收益最高的改动：

```sh
# 生成 128px 与 32px 版本，页面用 srcset，favicon 单独给 32px
sips -Z 128 public/brand/vibe-guide-mark.png --out public/brand/mark-128.png
```
预期：首屏字节从 640KB 降到 ~150KB（**-77%**）。

### 1.2 字号：56% 的声明小于 14px

全站 CSS `font-size` 分布实测：

| 字号 | 出现次数 | |
| --- | --- | --- |
| 7px | 3 | ← 小于 14px |
| 8px | 4 | |
| 9px | 10 | |
| 10px | **26** | |
| 11px | **29** | |
| 12px | **63** | |
| 13px | **38** | |
| 14px 及以上 | 134 | |

**小于 14px 的声明：173 / 307 = 56%。** 加上组件内联样式，全仓 `font-size: 9–13px` 共 **247 处**。

项目里已经有 `readability.css` 在零散补救（`main .lesson-crumb{font-size:13px}` 之类），说明团队也注意到了，但**底层 token 仍是小的**，所以每加一个新组件就再欠一笔。

**目标用户是"零基础普通人"，且相当比例用手机。** 12px 在 390px 宽的手机上是明显吃力的。

建议：定一条最低线（正文 ≥16px、辅助文字 ≥13px、**任何文字不得小于 12px**），再做一次全站清理，而不是逐处补。

### 1.3 侧栏涨到 ~1300px（这轮我引入的）

我把侧栏从「6 个阶段」改成「18 个节点」后，实测估算：

```
18 项 × 40px                    = 720px
6 个阶段标签 × 35px             = 210px
导航标签 + 从这里开始 + 完整路线图  = 82px
查资料 / 遇到不懂的词            = 128px
大家在做什么                     = 68px
侧栏 padding                    = 56px
──────────────────────────────────────
合计                            ≈ 1304px
```

| 视口高 | 需要滚动 |
| --- | --- |
| 900px | 404px |
| 800px | 504px |
| 750px | 554px |

**用户看不到"我走到哪了"**——因为当前节点可能在折叠线以下。移动端菜单（复用同一个 `Navigation`）也一样高。

建议（择一）：
- **只展开当前阶段**，其余阶段折叠（默认展开 1/6，高度降到 ~400px）
- 阶段标签变成可点击的折叠头
- 侧栏独立滚动条 + 自动滚到当前节点（`scrollIntoView({block:'center'})`）

### 1.4 3 处小字对比度不达标——都在我这轮新写的组件里

| 位置 | 颜色 | 对比度 | 要求 |
| --- | --- | --- | --- |
| `ToolEntries.astro` `.entries-limit`（12px） | `#94a3b8` | **2.56:1** | ≥4.5:1 |
| `ToolEntries.astro` `.entries-name span`（12px） | `#7b8ea5` | **3.36:1** | ≥4.5:1 |
| `Navigation.astro` `.nav-phase`（11px） | `#8a94a3` | **3.07:1** | ≥4.5:1 |

对比之下，本轮其余小字都合格（`#64748b` 4.76:1、`#b3283c` 6.39:1、`#7b5fc0` 4.95:1），正文与 muted 更好（15.8:1 / 6.11:1）。

**结论：配色体系本身没问题，是我在新增组件时随手挑了几个偏浅的灰。** 换成 `#64748b` 即可。

## 2. P1：结构层面的问题

### 2.1 单页交互元素过多

`node/preview`（4 个步骤）实测：

| 元素 | 数量 |
| --- | --- |
| `<details>` | **50** |
| `<button>` | **50** |
| `<a>` | **168** |
| `<textarea>` | **17** |
| `<select>` | 5 |
| `<input>` | 7 |

**50 个折叠块、17 个文本框，在一页里。** 手机上是一堵折叠墙。

来源：每个步骤内嵌「操作示意 + 9 个槽位（其中 4 个是可折叠 details）+ 2 个提示词编辑器 + 分支 + 示例 + 核对面板」。

建议：
- **步骤列表分页/分段**：一个节点一次只渲染当前步骤的完整内容，其余步骤只在展开时才挂载
- 或把「不会具体操作？逐项跟着做」「这一步出现的词」「问题不在列表里」合并成一个「更多细节」折叠

### 2.2 多步骤节点默认全部折叠

| 节点类型 | 节点数 | 默认状态 |
| --- | --- | --- |
| 单步骤 | 11 | **展开** ✓ |
| 多步骤 | **7**（含 preview 4 步、accept 3 步） | **全部折叠** ✗ |

`open={i === 0 && steps.length === 1}` 的结果：用户点进 preview，看到 4 个闭合的框，**首屏没有任何实质内容**。

建议：`open={i === 0}`——**第一个步骤永远默认展开**，其余保持折叠。

### 2.3 进度被记录但不显示

节点页实测：`data-progress` 元素 **0 个**，`data-complete` 元素 4 个。

也就是说：学习进度**会被写进 localStorage**（`initLearning` 负责），但节点页**没有任何地方把它画出来**。用户看不到「4 步里已完成 2 步」，也看不出哪个步骤打勾了。

建议：步骤摘要上加状态（`已完成` / `进行中` / `待做`），页头加「已完成 2 / 4」。

### 2.4 单页 71 个标题

`node/preview` 有 **71 个 h1–h4**（层级无跳级 ✓、无重复 ID ✓）。对读屏用户来说，按标题跳转要在 71 项里找路。

建议：槽位标题（「01 开始前带上…」）其实不是内容标题，可降为 `<p class="slot-title">` 或加 `role="presentation"`，只保留步骤标题为 h3。这样标题数从 71 降到 ~15。

### 2.5 路线图页仍塞着旧的 4 泳道 16 节点图

`dist/zh-cn/roadmap/index.html` 里有 **16 个 `/roadmap/<旧id>/` 链接**，藏在一个 `<details>`「查看完整知识路线与制作分支」里。

现在 18 节点已是唯一主线，这张旧图：
- 造成**第四套编号**（与 18 节点、31 步骤、6 阶段并列）
- 增加页面体积
- 用户可能误以为是另一条必走路线

建议：移除，或明确标为「历史资料，不再维护」。

## 3. P1/P2：可用性与无障碍

### 3.1 触摸目标低于 44px

| 元素 | 实测高度 | 位置 |
| --- | --- | --- |
| `.icon-button`（菜单、关闭） | 32×32 | `global.css` |
| `.languages a`（中文 / EN） | ~20px | `global.css` |
| `.header-search`（手机） | ~32px | `global.css` |
| `.template-copy`（复制提示词） | ~24px | `learning.css` |
| `.button` | ~36px | `global.css` |

只有 `.nav-item`（42px）与 `.learn-primary`（50px）接近或达标。

**注意**：`.template-copy`（复制提示词）是本产品的核心动作按钮，24px 在手机上很难点准。

### 3.2 移动端搜索按钮无可访问名称

`global.css` 在 `max-width:639px` 下把 `.header-search span` 与 `kbd` 设为 `display:none`，而图标是 `aria-hidden="true"` → **手机上这是一个没有名字的按钮**（WCAG 4.1.2 失败）。同样被隐藏的还有 `.help-button`，即「关于本次预览」的免责说明在手机端不可达。

### 3.3 新组件缺响应式与动效规则

| 文件 | `@media` | `prefers-reduced-motion` |
| --- | --- | --- |
| `ToolEntries.astro` | **0** | 无 |
| `Navigation.astro` | **0** | 无 |
| `NodePage.astro` | 1 | 无 |
| `NodeStep.astro` | 1 | 无 |
| `home.css` / `global.css` / `readability.css` | 8 / 8 / 4 | 有 ✓ |

`node/tool` 一页要渲染 **26 个工具**（115KB raw），在手机上是很长的一段，而 `ToolEntries.astro` 完全没有移动端适配。

### 3.4 首屏被 hero 占满

从手机截图（390×844，改动前）看：眉标 + H1（两行 30px）+ 三行导语 + 两个按钮 = **整个 844px 视口被占满**，用户必须滚动才看到任何可操作内容。

对于一个卖点是「跟着做一个动作，看到结果」的站点，首屏应该**至少露出路线或下一步**。桌面版同样：1440×960 里 H1 与导语占了大半，右侧大片留白。

## 5. 做得好的地方（不要动）

1. **层级与留白**——从截图看，标题、正文、辅助信息的层级清楚，留白充足，没有拥挤感。
2. **主次操作分明**——「接着上次的步骤做」实心按钮 vs「先看完整路线」文字链接，一眼能分。
3. **聚焦态覆盖完整**——全站 `focus-visible` 20 处、`:focus` 22 处、`outline` 13 处。
4. **正文对比度好**——主文字 15.8:1、次要文字 6.11:1，远超要求。
5. **HTML 结构干净**——`node/preview` 层级无跳级、**48 个 id 全部唯一**、`<main>` 地标存在、品牌图 `alt=""` 正确。
6. **`prefers-reduced-motion` 已在主要样式表覆盖**（`home.css` / `global.css` / `readability.css` / `ProjectRoadmap.astro`）。
