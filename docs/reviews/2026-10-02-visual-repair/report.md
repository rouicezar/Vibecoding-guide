# OpenCode 改动复核与视觉恢复

## 需求与边界

恢复用户已认可的路线图、全站间距与排版，修复不必要的窄栏换行。保持教程内容、站点结构、进度数据与有效流程修复。不将所有自然换行强行改成单行。

## 改了什么

1. 已提交的 a9ab059：修复排障返回来源节点、区分不适用与真实核对、统一17类需要本人核对的步骤；把可选发布步骤单列；增加节点工作量、首屏继续入口、提前展开术语的入口和路线图进度。这些实现及对应测试保留。本次 quality/verify 再次通过；不代表真人学员验收。
2. 未提交视觉改造：41个已跟踪文件，1905行新增、1608行删除，另新增 tokens.css 和视觉校验脚本。涉及颜色机械归并、字号统一、间距向上取整、首页背景和卡片定位、节点页标题与路线图结构。
3. 视觉校验把零字面色、限定字阶和4px间距当作硬指标；这些指标本身不能证明布局正确。换行检查只比较文本与当前栏宽，无法发现“不合理窄栏导致的换行”；也未覆盖折叠后才可见的全部说明。

## 问题与处理

- 路线图：连续渐变SVG被替换成每行CSS横线及竖线，竖线会穿越文字；260px固定行高容不下加大字号和多行说明。恢复原连续弧形路线及阶段色；保留进度。阶段按内容自适应，留32px下间距，连线根据圆心和实际行高重绘；窄内容区使用原竖向路线，避免侧栏挤压后仍强排多列。
- 全站间距与层级：批量抬高字号和向上取整间距改变了已确认的视觉比例。恢复至视觉改造前的a9ab059，包括组件样式、主样式、首页背景及视觉改造专用门禁；其已提交流程功能不回退。
- 说明标签：100px固定栏在改造前已存在，字号放大进一步加剧。所有节点共用的micro-check改为基于实际容器宽度响应：宽处max-content标签列，窄处标题在上、正文在下；保留英文长句的必要自然折行。
- 首页：恢复后实际检查又发现中英文桌面卡片有重叠，故把已验证的手机内容流布局扩展到全宽度，保留错落排列、24px间距与原装饰风格。
- 未删除内容换行或代码示例换行；没有使用全局nowrap掩盖问题。
