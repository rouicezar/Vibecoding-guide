# 产品需求：零基础 Vibe Coding 实践指南

状态：2026-09-23 根据用户的 12 项要求修订，替代原六栏目方案。所有数量、页面和效果要求属于规划，不代表已实现。面向读者的完整内容骨架见 [站点总规划](site-blueprint.md)。

## 1. 主张与受众

**AI 时代，即使零基础不懂代码，也能 Vibe Coding。**

帮助普通人选定要做的产品、说清想法、指挥 AI 小步完成、亲自检查并持续使用。读者不需要先学编程语言或照着代码操作；应能理解选择理由、表达限制、检查结果、知道失败后的下一步。

项目分四类：Web 站点、小程序、手机 App、桌面端 App。Web 是第一次做最小可用产品的默认入口；手机和电脑应用面向已有网站制作经验的人；小程序按实际用户所在平台选择，覆盖微信、支付宝、抖音等，先做一个平台。

本站仍是知识与实用辅助站点，首期无需账号。向用户介绍后端和 App 制作，不等于本站要提供账号后台或直接制作四种应用。暂按免费公开内容设计，商业模式未确定。

## 2. 信息架构

首页以 Slogan、用途说明和四类项目入口为核心，同时给已有项目的人提供按问题搜索与跳转。顶栏四组导航：做项目、和 AI 沟通、界面与功能、检查与上线。搜索常驻，术语解释作为全站辅助能力。

## 3. 用户流程

新手：选择网站 → 明确一件事 → 缩小第一版 → 选择工具与搭建方式 → 描述页面 → 完成主要操作 → 检查 → 正式开放 → 照看。

有经验者：选择手机或电脑 → 确定目标设备 → 补设备特有需求 → 真机/实际电脑试用 → 安装与保存检查 → 对应渠道发布与更新。

小程序：选择平台 → 核对能否开通目标功能 → 制作与平台内试用 → 保存/访问检查 → 准备材料 → 提交平台检查 → 正式入口验证。

查问题：按生活化现象搜索 → 确认预期与实际 → 补必要证据 → 只检查一个可能原因 → 修正与复测 → 成功或下一分支。

## 4. 首轮交付与后续完整覆盖

首轮可用版应覆盖全部主题的入口和基本解释，先把网站路线做成完整的可操作内容流程；其他三类至少有真实可读的概览、准备清单、基本步骤与对应下一步，不用空页面占位。

首轮内容要求：四条基本路线；工具/搭建方式的区别及方案选择说明；12 个沟通模板；前端、后端、检查、上线、维护五类指南；30 个核心术语；12 张排查卡。数量仅用于管理制作范围，不能代替编辑验收。

组件词典保持 212 个稳定词条、25 类和旧资料，首批校准 12 个常用演示；其余明确验证状态。中文话术优先，英文名称用于搜索和精准沟通。

完整覆盖阶段：按微信/支付宝/抖音、Android/iPhone、Windows/Mac 分别补平台操作教程与实例验证；增加每条路线的案例与对应安装/发布/更新记录。基本流程、具体操作和实测结果分别记录状态。

首期交互限于项目选择引导、搜索筛选、话术填写与复制、可视演示、按问题分流。基于确定性规则在本地生成说明，不调用模型。收藏、进度保存、导出说明包放后续；账号、收费、社区、执行用户项目和自动修复不在当前范围。

## 5. 内容和体验约束

每条内容按照：问题 → 准备 → 逐步动作 → 给 AI 的话 → 成功标志 → 失败下一步 → 相关内容。页面主标题不用未解释的技术名词作为唯一入口；标准名保留在副标题、术语解释与搜索别名。

沟通模板显示完整输出，缺信息提示补充，复制实际成功才显示成功。排查区分事实与猜测，不把泛化重装或关闭安全保护当作默认操作。

搭建方式按项目、设备、资料、共享、费用和维护条件选择，最多给两个合理候选并解释区别；“我不知道”是有效答案。具体工具功能、价格和平台要求发布前核对官方来源及日期。

视觉执行 [设计规范](design-system.md)：参考 OpenRouter、Hugging Face 和 GitHub 的克制工程风格，保持浅色、精细排版与统一线性图标。

## 6. 验收

- 从首页能理解 Slogan，选择四种项目并进入对应路线；零基础网站入口清楚。
- 每个主题至少有完整话术、可执行动作和完成标志；不以链接到开发文档代替白话解释。
- 手机与电脑路线包含实际设备、保存、安装和更新；小程序按平台区分；上线与运维不只面向网站。
- 检查内容引用、来源日期、搜索口语命中和复制反馈；首期 212 个词条不丢失。
- 找 5 位无编程基础的人完成项目选择、描述界面和排查任务，目标至少 4 人无需作者解释完成。没有真实试用就记录待验证，不提前宣称效率提升。
- 页面能打开、功能实际可用、普通人能理解、已公开上线分别记录。
