# 产品需求：面向普通人的 Vibe Coding 实践指南

状态：筹备方案，2026-09-23。基于用户本次目标制定；范围、数量和指标是规划，不是已完成或已验证效果。

## 1. 产品目标与边界

让没有编程基础的人从“我想做一个东西”走到“我知道如何指挥 Agent、检查结果、解决卡点并交付”。组件词典是其中的“表达界面”子模块。

用户需要理解自己的选择和结果，不需要学习编程语言、手写代码、背诵框架清单或调试调用栈。正文以日常问题、操作步骤、可复制话术和可观察结果组织。确需终端操作时，优先提供“让 Agent 执行并解释结果”的方式；不把不透明命令包装成零门槛解决方案。

首期面向中文用户、以桌面查阅和边做边用为主，同时支持手机阅读。暂按免费公开内容、无需账号、自主维护内容设计；这是可调整假设，不承诺商业模式。

## 2. 核心用户任务

| 我遇到的问题 | 站点给我的东西 | 完成标志 |
| --- | --- | --- |
| 工具这么多，我选哪个？ | 按设备、预算、项目类型、安装意愿筛选的选择指南 | 选出适合当前任务的一类工具，知道限制和第一步 |
| 脑子里有想法，说不清 | 项目需求表和沟通模板 | 得到包含目标、范围、约束、验收方式的完整说明 |
| 我想要这种界面，但不知道名称 | 可视组件词典和容易混淆的对比 | 找到正确组件，复制并调整描述 |
| Agent 问我要不要后端、数据库，我不懂 | 场景化术语解释与选择分支 | 能按真实需求回答，而非照抄技术名词 |
| 项目做了一半，不知道先做什么 | 分阶段任务路线和验收清单 | 明确当前阶段、下一步及进入下一阶段的条件 |
| 页面打不开、保存失败、越改越乱 | 根据现象分流的排查卡 | 收集有用证据，执行一个检查并判断下一步 |
| Agent 说做好了，我怎么确认？ | 用户操作验收、交付和恢复清单 | 能亲自走通核心流程，理解未完成事项 |

## 3. 信息架构

首页首屏使用“你现在卡在哪一步？”和自然语言搜索，不要求先认识术语。推荐入口为：不知道怎么开始、不会描述需求、效果不对、遇到报错。保留六个稳定栏目：

| 栏目 | 规划路径 | 主要内容 |
| --- | --- | --- |
| 开始做项目 | `/start/`、`/workflow/` | 项目选择、最小范围、完整流程和阶段清单 |
| 选工具 | `/tools/` | 工具类型、条件选择器、具日期和来源的工具卡 |
| 和 AI 说清楚 | `/communicate/` | 需求、修改、参考图、反馈、排查、交接模板 |
| 找界面组件 | `/components/` | 当前词典，按外观和用途搜索，展示差异与演示范围 |
| 看懂术语 | `/terms/` | 日常解释、项目影响、选择问题、可复制话术 |
| 解决问题 | `/troubleshooting/` | 按症状分流、取证、单步检查、验证与恢复 |

案例穿插各栏目并在 `/projects/` 汇总；不为案例再增加一套重复教程。全站搜索 `/search/` 支持别名和生活化描述，结果显示“你能解决什么”，不只有技术标题。

## 4. 三条完整使用路径

### 从零开始

“想做活动报名页” → 明确给谁用、收哪些信息 → 判断是否需要共享保存与管理权限 → 选择工具类型 → 生成需求说明 → 先做能报名的一条流程 → 用虚构数据验收 → 查看上线与后续维护清单。

起步示例先使用“个人作品展示页”，避免同时引入账号和数据权限；报名页作为需要共享数据的第二个案例。

### 精准表达

搜索“点一下下面出现一条线” → 对比 Tabs 与 Slider → 操作演示 → 填写文字、位置、切换内容与状态 → 复制中文描述 → 检查 Agent 的产物是否真的切换内容。

### 遇到问题

“保存以后刷新就没了” → 记录操作、页面和数据是否真实保存 → 区分本机保存与多人共享 → 复制诊断说明 → 要求 Agent 先给证据再改动 → 按相同步骤重试 → 成功结束或进入下一分支。

## 5. 第一版范围

- 首页任务入口、六个栏目、单条内容详情和全站搜索。
- 一套 8 阶段项目路线；每阶段都有输入、动作、验收、下一步。
- 6 篇工具选择指南、12 个沟通模板、30 个核心术语、12 张排查卡、2 个贯穿案例。
- 当前 212 个组件词条完整保留可查；先重点校准 12 个常用组件的内容与演示，其余明确注明“简化演示，未完成逐项行为验证”。未验证不能标成完整实现。
- 首期工具选择器输出工具类型、选择理由与限制。具体品牌卡完成实时官方资料核验后再上线，不做未经验证的“最佳工具”排名。
- 首期交互：按条件选择工具、填写并生成沟通说明、搜索/筛选组件、复制反馈。生成内容使用本地确定性模板，无模型调用费用。

收藏、项目进度本地保存、导出项目说明包放下一阶段；账号、云同步、付费、社区、在线执行代码、自动修复用户项目、内置 AI 聊天不在首期。

## 6. 页面与交互标准

视觉方向已由用户指定：参考 OpenRouter、Hugging Face、GitHub 产品界面的克制技术工程风格；统一排版、层级和线性图标，执行 [视觉规范](design-system.md)。

内容页面固定展示：这是哪个问题 → 先做哪一步 → 详细步骤 → 可以这样告诉 Agent → 如何判断成功 → 没成功怎么办 → 相关术语与下一步。

术语解释默认简短，深入解释按需展开。复制前能看见完整内容；缺必要信息时提示补充；失败不显示成功；可手动选中文字作为回退。模板占位符必须显眼，不把虚构资料误当用户真实数据。

工具选择器允许“我不知道”，用项目场景追问，不强迫新手选择框架；每个结果附“为什么适合 / 哪种情况不适合 / 可以先试什么”。不用武断评分代替解释。

无结果时展示更常见说法和邻近问题。筛选后保留输入；详情有稳定地址和返回路径。键盘可操作，手机无横向溢出，减少动态效果设置生效。

## 7. 内容验收与效果验证

发布前为每篇做编辑验收：能否用一句话说明用途？步骤是否可执行？是否有完成标准？有没有未解释的新术语？事实有没有来源和日期？遇到失败是否有后续路径？

找 5 名无编程背景试用者，分别完成工具选择、组件描述、失败排查。目标为至少 4 人无需作者解释完成指定任务；记录误解点、完成时间和返工次数。该目标是待验证门槛，不能提前宣称提高效率或精准率。

技术验收另行验证：内容链接与引用无断链、搜索命中预设问题、复制成败状态正确、关键路径键盘和手机可操作。构建成功不等于普通人会用。
