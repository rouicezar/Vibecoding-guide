# 产品需求：零基础 Vibe Coding 跟做指南

更新：2026-09-29，依据用户本轮明确纠正。本文是当前产品目标与范围的依据，替代本文件此前混合的历史规划。现有实现数量和发布状态另见 [当前路线](current-route.md) 与 [任务记录](../tasks/todo.md)，不能反过来限制教学目标。

## 1. 唯一目标

让没有编程基础的用户来到网站，选择一个实际可用的工具，依据本站的步骤、示范和方法，亲手操作该工具，逐步做出自己的可运行项目，并理解怎样检查、处理问题和继续维护。

本站提供教学，不提供项目开发服务。教学质量以用户能否知道下一步在哪里做、怎样做、看到什么、失败怎么办，以及前后能否接得上判断。内容数量、代码构建通过、参考程序能运行，都不能单独证明教会了用户。

## 2. 网站、用户和工具的边界

| 角色 | 负责什么 | 不应混淆的边界 |
|---|---|---|
| 网站 | 说明目标和准备材料；逐动作示范；给对应提示词、图片、即时提醒、结果对照和恢复方法；提供查阅资料 | 不读取用户项目目录，不替用户安装、写代码、运行项目、连接数据库、部署或自动修复；本站进度是学习者自记，不是项目自动验收 |
| 用户 | 选择工具；找到入口；填写自己的材料；把任务发送给工具；打开实际结果；试用、判断和记录 | 不要求先学会编程，也不能只点本站“完成”而未操作；费用、账号、公开发布等由本人决定 |
| 用户选择的 AI 工具 | 在该工具实际权限内读取项目、生成文件、运行命令、检查和协助修复 | 工具不是本站内置执行器；AI 回复“完成”必须通过真实产物和用户操作核对 |

站内模板填写、复制、搜索、项目材料和本地进度用于辅助学习，不代表已经修改用户项目。参考代码仅作为编辑核对教学可行性的材料，不替代逐步教学，不成为用户必须下载的成品。

## 3. 教学方法：示范一个动作，带着做一个动作

每个可以独立执行的小动作按实际操作顺序组织：

1. **现在在哪里**：指出在本站、所选工具、文件管理器还是作品页面操作。
2. **示范怎么做**：具体到选择哪个对象、输入什么、点击什么。需要定位时配对应图片；分系统或工具的差异要说明。
3. **用户跟着做**：只给当前需要完成的动作。需要提示词时当场提供或直接定位到本步模板，明确填写、确认、复制、粘贴、发送各自的入口。
4. **即时提醒**：在容易操作错的那个动作旁提醒，不集中到文末才说。
5. **观察结果**：给能亲手检查的文件、画面、内容或反馈；说明等待期间可能发生什么。
6. **卡住就处理**：给一个具体检查和恢复入口；结果不符时不催促进入下一步，不默认重装、清库或重建项目。
7. **接着做**：明确把什么材料带到哪个动作。示范、操作、检查之间不能依赖学员自己补全隐含步骤。

提示词是某个操作用到的教学材料，不是整堂课。不能用“复制这段让 AI 做”替代找到工具入口、发送、等待、查看结果和处理失败的教学。填写类材料与给 AI 的指令要区别呈现，示例验收结果不能替学员填成通过。

## 4. 内容范围与框架

当前网站布局、UI 设计和逻辑结构固定，不再调整。只在现有阶段、节点页、动作详情、资料库、术语等位置完善步骤、提示词、说明、示范素材和资料内容，不新增交互或修改展开、导航、进度、模板流程。

**31 个动作不是标准，也不是上限或下限。** 阶段、节点、动作和微操作的数量均是实现快照。必要时在现有步骤内容中拆细操作、增加缺失交接、合并重复说明，不为维持数字压缩教学，也不为增加规模扩充内容。若确需新增顶层动作、修改导航或进度逻辑，先记录教学缺口和影响，本轮不实施结构变更。

用户可以用自己的想法跟做；示例帮助理解，不能把示例需求强加给所有项目。选择有前端、后端、数据库的项目时，必须教到三者的实际连接、保存读取、异常处理、重启和维护，不能用页面模拟或浏览器缓存冒充数据库。先本机可运行也是有效成果，公开发布按用户项目需要选择。

现有 Web、移动、桌面及小程序资料继续作为对应类型的教学支持，不在本轮重建整体架构。当前优先补齐首次操作、文档交接、开发、检查和恢复路径。

## 5. 工具、图片和语言

- 用户选择一个实际可用的工具完成项目；Codex 可作为演示工具，不要求所有人安装所有工具。
- 入口图必须服务某个动作：圈出操作目标、说明操作前后和对应文字。真实截图注明工具、界面语言及采集日期；不出现个人信息。
- 生成图和概念示意必须标注，不能作为已核实的真实按钮位置证据。没有真实素材时明确记录图片缺口，不虚构截图。
- 工具版本不同须给功能名称或官方入口查找方法；官方文档仅作依据，不能代替本站白话操作说明。
- 中文面向完全零基础；术语首次出现就地解释。英文同步表达相同操作和边界。避免“初始化即可”“接好接口”等省略真实操作的说法。

## 6. 本轮实施要求

先完成需求与边界修订，再完善现有框架中的首批连续跟做：选工具、创建文件夹、打开项目、准备起点、打开真实文件；接着细化环境和预览的操作交接。

首批动作在现有逐项操作区补齐位置、具体操作、及时提醒、预期和失败处理；沿用当前展开方式和提示词模板，不新增往返入口。保留现有材料和进度，不另建项目执行后台、不新增站内 AI 开发能力。

编辑验证与学员验收分开记录。可以用隔离参考程序检验方法，但不能以开发该参考程序代替完成教学整改。后续按教学缺口继续逐步补全，不预先限定动作总数。

## 7. 验收及证据

- 从一个真实起点按页面顺序走，前一步产物能作为后一步输入；没有突然要求尚未建立的文件、账号、服务或知识。
- 每个本轮改动的小动作具备位置、具体操作、提醒、可观察结果和失败处理；当前只完善已有操作区的内容，不改变阅读区布局及展开逻辑。
- 需要提示词的地方明确指出现有模板的位置，说明填写、确认、复制、粘贴、发送和检查结果的顺序，不改变现有交互。
- 图片和示范不冒充学员结果，站内保存与用户项目保存明确分开。
- 保留用户既有学习资料，检查双语、手机阅读、链接、复制、导航与适用进度行为。
- 分别记录内容核对、技术检查、作者跟做、外部工具执行和学员试用。没有哪项证据就不宣称哪项完成；不擅设固定人数或成功率门槛。
- 本轮不自动发布，完成后报告可审阅变更、已验证结果与剩余教学缺口。

## 8. 最新教学表达标准（2026-09-29，全步骤整改）

以用户确认的第 2 阶段 Git／AGENTS.md 教学为标准，覆盖全部现有步骤及修复、可选分支：

- 先用日常语言说明用途。例如 Git 保存每次提交的代码版本，出错可回到之前已保存的版本；AGENTS.md 是写给 AI 工具的项目说明书和规则。不得写成“可恢复的起点与 AI 工作约定”让新手自行翻译。Git 不会自动保存一切，初始化后仍需提交版本。
- 一次只教一个动作：告诉用户在哪里操作、具体做什么，当场提供对应提示词，再告诉用户完成后看哪里。初始化 Git、创建 AGENTS.md、保存项目说明、提交第一个版本分别教，不能塞进一个总括句。
- “03 你要做的”直接提供可跟做的操作和邻近提示词。操作不能只放在折叠的补充说明中；已有提示词编辑器保留，说明分步发送后不必重复发送整段模板。
- 删除“本站不能检查你的电脑文件”等对当前操作无帮助的站点能力声明。直接教用户在所选工具中查看文件、把结果保存到指定文件。保留真正影响操作的提醒，例如保存版本前排除密码、恢复备份不能覆盖原数据。
- 用具体对象替换抽象词：文件名后说明用途，说明按钮点完发生什么；“产物、交接、核验、边界、回归、放行”等不能单独充当教学解释。
- 全站步骤标题、节点简介、用途、动作、提示词、预期和失败处理统一遵循该标准，中英文同步。沿用现有页面区块、节点、导航和进度逻辑；仅为动作和提示词的分段阅读使用既有段落、提示词文本样式，不新增交互或重做 UI。

验收：逐步骤核对“一项动作、一段对应提示词、一个可见结果”；需要人工填写或点击的动作直接给操作，不强塞 AI 提示词。Git 示例不得承诺找回未提交、被忽略或库外的数据。技术验证之外，仍需真实初学者试走才能证明学会。
