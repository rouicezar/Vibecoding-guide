## 一、整改目标与不变的优点

目标不是让页面看起来更简洁，而是让第一次接触的人能够回答：

1. 我现在只需要做什么？
2. 在哪个软件、哪个位置操作？
3. 做完应看到什么，怎样知道可以继续？
4. 我的画面不一样或失败了，点哪里求助？
5. 解决以后怎么回到刚才那一步？明天回来怎样接着做？

保留：本人先记录想法、未知可以保留、AI 一次问一个关键问题、控制第一版范围、可用提示词、可恢复记录、真实使用检查、发布与付费由人决定。保护措施放在实际相关的步骤，不要求用户先理解全部工程概念。

不把“代码由 AI 实现”视为缺陷；重点补齐人需要操作、选择和判断的环节。学习完成、操作完成、实际验证、公开发布分别记录。

## 二、新的页面层级

### 1. 首页：只解决从哪里开始

新用户看到站点用途、最终能做出什么的真实例子，以及一个主要入口“开始我的第一个项目”。已有学习记录时突出“继续上次步骤”。“查资料”“浏览完整路线”作为次级入口。

不在首屏展示十三节点全图、全部工具、长提示词和排障目录。已有项目的人仍可直接查资料，不强制从第一课开始。不给未经实测的“十分钟学会”或完成率承诺。

### 2. 父层：一个阶段的目标

建议先用六个易懂的阶段组织，作为原型方案验证：

| 父层 | 对用户的说明 | 原内容归属 |
| --- | --- | --- |
| 想清楚先做什么 | 记下自己的想法，选一件小事开始 | 想法草稿、项目类型初步判断 |
| 让 AI 准备好开工 | 找到工具，打开项目，让 AI 确实创建一个文件 | 工具、项目位置、能力检查、必要的版本与规则准备 |
| 一起确定第一版 | 回答问题，确定哪些要做，让 AI 整理制作安排 | 澄清、范围、需求、选型、计划 |
| 做出能用的小版本 | 看第一张页面，再走通一条真实操作 | 环境、界面、必要的数据、完整流程 |
| 亲手试一遍 | 对照原想法检查，发现问题后修好 | 测试、本人验收 |
| 决定怎样使用和继续改 | 自用可以在本机停下；需要分享才进入上线 | 发布、维护、新需求与故障分流 |

父层默认只显示本阶段目的、可辨认的完成结果、简短子步骤目录、继续入口。进入父层后按子步骤执行，必做操作不能藏在“遇到问题”里。

原十三节点和三个开发分支保留内容与映射；阶段数只是阅读组织，不意味着省掉其中关键步骤。不要为了压成六个阶段，把不同动作合并成模糊的一步。

### 3. 子层：当前只做一个能检查的动作

每页或每个当前步骤固定呈现：

- **现在做什么**：例如“打开刚才创建的文件夹”。
- **在哪里做**：工具名称、当前界面、具体按钮/菜单，与对应截图。
- **操作**：短而连续的动作；需要发给 AI 时才出现本步话术。
- **应该看到什么**：真实结果图、可辨认的文字或文件，标出关键位置。
- **结果选择**：“我看到了，继续”“没有看到/遇到问题”。不以“读完了”替代完成。

必要费用、授权影响和会影响资料的决定直接出现在相关动作前，不能藏入深层。用户可以预览后续步骤，不能因为未打勾而被强制锁住。跳过时说明适用条件和缺少什么，不伪造完成状态。

### 4. 子子层：按现象解决问题

“没看到文件”“按钮名字不同”“一直在等待”“提示没有权限”“AI 只回复了文字”等采用用户实际看到的现象命名。

每条问题路径包含：看到什么→先检查一件事→具体处理→处理后应看到什么→返回原动作。仍失败时，提供可复制的求助材料、下一项检查或明确停止点，不能只循环说“再问 AI”。

短解释可在原位展开；较长排障进入独立子页并保留面包屑、输入和返回位置。避免弹窗套弹窗、多个滚动区域和无限折叠。三层之后的术语/原理作为资料链接，不继续制造深层操作迷宫。

### 5. 视觉规则

- 主要内容始终围绕当前步骤，一个主要前进操作；问题入口作为清楚的次级操作。
- 页面标题、动作、结果、问题四种视觉角色稳定；不靠大量彩色卡片区分所有内容。
- 桌面只保留紧凑学习位置；资料目录按需展开。手机不先铺一整条长路线。
- 提示词只在需要发送时出现；参考资料、为什么这么做、其他工具选择逐层打开。
- 截图必须匹配所写工具/系统，并带核验日期；示意图明确标注，不能代替操作截图。
- 返回、浏览器后退、刷新、键盘和搜索直达都能到同一个明确步骤；折叠内容仍能被搜索并在到达时展开。

## 三、第一条整改路线：先完整做成一个小项目

首轮只把一条路线做到足够细，再扩展。建议采用“个人学习记录网站”作为可跟做的示例：填写→保存→查看→刷新仍在，不做登录、多人共享或支付。用户仍先填写自己的想法；可以选择跟做示例，不强迫自己的项目变成统一案例。

首轮工具路线暂以 Mac + Codex 为候选，因为现有环境可以核验具体界面；在内容采集阶段确认入口与可用性后固化。它是教学示例，不是工具排名。Windows、网页工具及其他已支持资料保持可访问，但没有走通前不标为同等完整课程。

从零应覆盖以下动作，而非假定用户已经会：

1. 看懂练习目标，写下自己的想法，理解本机使用与分享给别人的区别。
2. 确认电脑系统、工具可用性、账号与费用条件；找到官方入口，完成必要安装和登录。需要用户完成的验证如实交接。
3. 在明确位置新建项目文件夹，取一个示例名称，说明名称可自行替换。
4. 在工具中打开该文件夹，找到当前项目的对话入口。
5. 发送一个小任务，让 AI 创建说明文件；亲自找到并打开，确认不是只有聊天回复。
6. 让 AI 保存想法、准备规则和可恢复起点；用户只检查可以辨认的结果，不必先背 Git 命令。
7. 一次回答一个问题，确认第一版及暂不做事项；让 AI 整理需求和计划，提供短的产物对照。
8. 让 AI 准备运行条件，找到预览入口，看到第一张属于自己项目的页面。
9. 按小任务完成输入、保存、查看；遇到错误进入对应现象分支。
10. 检查空内容、保存成功、刷新和重开；只在本机的项目不要求跨设备同步或多身份验证。
11. 关闭工具后按教程重新启动，继续原项目；模拟换 AI 对话，找回材料与下一任务。
12. 作出“本机自用完成”或“继续分享”的选择。后者进入一条单独验证的 Web 发布路线，不能把 localhost 当正式网址。

每个动作都要有正常路径、至少一个实际常见异常、结果对照和返回点。异常以观察和对应官方说明核对，不凭空编造失败画面；未能实际触发的故障明确标记为资料整理。

## 四、分阶段执行与交付

| 阶段 | 工作与交付物 | 通过依据 |
| --- | --- | --- |
| R1 内容梳理与步骤拆分 | 将现有节点、模板、工具、排障分别归到阶段/动作/问题/资料；建立首条路线步骤表；每步注明用户动作、AI动作、输入、结果、异常与返回位置 | 从没有工具到重新打开作品没有“默认已经会”的空白；保留原资料和未完成标记 |
| R2 可操作原型与视觉层级 | 首页、阶段页、单步操作页、问题子页、恢复学习入口；优先用“打开项目→创建文件→看不到文件→处理后返回”做桌面和手机样板 | 可以顺着操作、进入问题、返回继续；不需要在一屏众多模块里找下一步；用户可审阅具体原型 |
| R3 真实内容与完整示例 | 核验一个工具的实际界面；从空文件夹制作示例，保留每步截图、短产物样例、真实错误与修复；补重新启动和换对话 | 未用教程外的作者口头补充仍能执行；任何执行者临场补充必须记录并补回教程后重走 |
| R4 学习页面与交接实现 | 用已验证样板实现分层导航；本机学习进度与草稿、明确保存状态、导出材料；提示词带当前条件，修改后避免复制旧内容；搜索直达步骤/问题 | 刷新或返回不丢当前学习位置；表单和复制内容一致；排障返回原步；搜索不再落回无关首页 |
| R5 扩展与旧内容接入 | 修正本机/共享数据分流；把工具比较、术语、组件作为按需资料；补一条明确平台的Web发布路径；旧链接兼容、双语对应 | 所有旧入口有去处；查资料后可回原任务；中英不出现半迁移混用；其他平台未实测状态清楚 |
| R6 新手试用与修订 | 先小范围发现卡点，修订后组织原计划中的5位真实零基础使用者；记录求助、误读、放弃位置和实际完成结果 | 至少4位无需作者口头解释完成明确试用任务；失败步骤继续整改，不能拿AI模拟或构建通过替代 |

顺序：R1 → R2 → R3 → R4 → R5 → R6。R3可以根据实操结果修正R2，不先把错误教学固化为全站组件。每阶段保留可审阅产物；小批实现并验证后提交，按项目远程与发布授权处理推送/上线。

**第一次可审阅交付是R1+R2，不是全站一次重做。** 它应包含一个真正可点开的正常路径和救援路径，让用户直接判断是否符合本次讨论。

## 六、如何判断整改有效

### 页面和行为验证

验证正常前进、失败进入子层、解决后返回、浏览器后退、刷新、关闭重开、换步骤、改条件、复制、搜索落点及手机菜单。学习进度保存只代表用户标记，不等于项目已经测试通过。

保持现有类型/构建/内容链接检查，并补受影响的实际交互验证。保存失败有明确提示，不能显示已保存；不因新增进度功能而引入账户、上传个人项目材料或默认跨设备同步。

### 真正的新手验收

任务A：未预先打开项目，按教程找到工具入口、建立项目并看到AI创建的文件。

任务B：按示例做出记录页面，保存一条记录，刷新后找到；遇到预先说明的隔离测试问题时，自己找到救援路径并回到流程。

任务C：停止后再次进入，重新打开自己的作品，继续下一项。

任务D：仅针对发布路线参与者，从测试入口完成到正式入口的交付；需要账号/费用/发布批准的环节单独记录，未完成不能记上线通过。

记录完成与否、第一次犹豫在哪里、求助次数、实际用语、误判了什么、是否丢材料、对照画面是否匹配。不预设分钟数或编造成功率；先取得基线。正常使用AI属于任务本身，作者额外口头解释属于需要记录的介入，两者不能混淆。
