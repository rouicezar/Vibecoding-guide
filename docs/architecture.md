# ADR-001：内容站点与局部交互的技术选型

日期：2026-09-23。状态：本轮选定的实施方向；尚未安装依赖或完成技术原型。

## 需求判断

问题不在于浏览器最终显示 HTML，而在于当前把 212 个词条、样式、演示和页面控制塞进一份 2,253 行文件，并维护多个副本。继续手工扩展会使多页面路由、内容关联、搜索、校验和多人维护越来越困难。

新站的主要负载是可检索的中文知识内容，加上少量高价值交互。目前没有已确定的登录、私有数据、实时协作或模型调用需求。应支持未来扩展，但不为尚未存在的后台业务付出首期维护成本。

本轮新增手机、小程序、电脑的教程内容，不改变本站作为内容站的定位；12 个板块与布局层级以 [页面与内容架构](page-content-architecture.md) 为准，内容话术参见 [站点总规划](site-blueprint.md)。开发本站的技术栈与向读者介绍的候选技术栈分开记录。

## 选择结果

| 层次 | 选型 | 职责 |
| --- | --- | --- |
| 页面与路由 | Astro，优先静态生成 | 栏目、详情、SEO、统一布局 |
| 类型与内容校验 | TypeScript strict + Content Collections schema | 校验必填字段、引用、分类和状态 |
| 交互 | React islands | 工具条件选择、沟通表单、组件演示；按需加载 |
| 内容 | Markdown 为主；MDX 仅用于可信仓库内容；JSON 保存结构化词典/规则 | 内容和界面分离，稳定 ID 相互关联 |
| 样式 | 原生 CSS + CSS variables 设计 token | 统一颜色、字体、间距与响应式，按组件组织 |
| 图标 | Lucide 按需 SVG | Astro 静态图标与 React 交互图标使用同一设计语言 |
| 搜索 | Pagefind，构建后生成全站索引 | 中文正文、别名和日常描述；无需独立搜索服务器 |
| 状态 | React 局部状态；后续必要时 localStorage | 首期无全局状态库；不存敏感信息 |
| 依赖管理 | npm + package-lock.json | 单包工程，锁定可复现安装 |
| 验证 | Astro check、内容校验、Vitest、Playwright | 分别验证类型、数据规则、分支逻辑和关键用户流程 |
| 部署 | 首期静态产物，可部署到兼容静态托管 | 具体服务随地区、域名、费用确定，当前不绑定供应商 |

脚手架阶段核对稳定版本、Node 要求和插件兼容性，在 `.nvmrc`、`engines` 与锁文件固定；本阶段不猜测版本号，也不声称这些依赖已安装。

## 方案比较

| 方案 | 优势 | 对当前任务的代价 | 决策 |
| --- | --- | --- | --- |
| 继续单 HTML | 现成、零构建 | 内容与演示耦合，多页面和校验靠手工 | 保留旧版参考，不作为新主架构 |
| Vite + React SPA | 适合持续交互的应用 | 内容路由、预渲染和搜索集成需另组织 | 不选为首期主架构 |
| Next.js + React | 具备服务端与客户端组件，适合复杂应用演进 | 当前内容站不需要大部分应用服务能力 | 若以后产品重心转到账号工作台，再评估 |
| Astro + React | 内容集合、静态页面和独立交互区域契合当前需求 | 要管理 Astro/React 边界，不能随意共享组件状态 | 采用 |

这是依据本项目需求的判断，不是框架能力排名。即便将来增加少量动态接口，也不意味着必须重写整站；Astro 可通过适配器对指定路由按需渲染。大规模私人工作空间/实时协作出现时，另写架构决策。

## 规划目录（尚未创建）

- `src/pages/`：首页加 11 个板块、下级主题/步骤、详情和辅助搜索路由。
- `src/layouts/`：站点与内容页布局。
- `src/components/`：通用展示组件；`interactive/` 放 React 交互。
- `src/content/`：教程、术语、模板、排查、AI 工具与搭建方案内容。
- `src/data/`：12 模块注册表、组件目录、项目路线索引、选择规则、别名映射。
- `src/content.config.ts`：内容 schema 和引用关系。
- `src/styles/`：设计 token、基础样式。
- `scripts/`：数据迁移、链接与内容验证。
- `tests/`：规则测试与端到端用户流程。
- `public/`：图片等公开资源；不得将整仓库复制到此目录。

单仓库、单应用，不建 monorepo、不引入独立后台。原资料、任务记录和历史脚本位于源码发布范围之外。

## 运行与交互约束

页面视觉以 [design-system.md](design-system.md) 为准，首期浅色工程风格；token 集中管理，不按页面临时选色。

内容 schema 按 `docs/page-content-architecture.md` 和 `docs/content-plan.md` 扩展模块主归属、相关模块、L1–L4 层级、专业名称引用、白话摘要、项目类型、平台、阶段、验收与下一步。模块注册表恰好包含首页和 11 个板块；小程序、工具和术语不增加顶层模块。tools 表示 AI 助手，stacks 表示搭建方案；共用教程由路线 ID 引用，不能为每个平台复制整套解释。

正文和可索引提示词在构建时输出，不能只在浏览器运行后出现。React 只接管需要状态的区域；演示按可见性或操作加载。词典列表分页/分批展示，详情有稳定 URL，不一次挂载 212 个复杂演示。

同一交互流程放在同一个 React 根内；跨页状态优先用 URL 参数表达，不默认引入全局 store。复制必须等待写入结果，失败提示手动复制。localStorage 读写有异常回退，禁用存储不能使页面无法渲染。

沟通模板和工具选择规则确定性生成、可测试、可解释。首期不接远程模型，输入不上传服务器。MDX 仅限维护者提交的可信内容，用户输入不作为可执行内容。

搜索页面设置 `zh-CN` 并核对 Pagefind 中文分词构建；索引包含中文别名、英文名称、症状词，不纳入内部文档和未发布内容。验收用“下面会动的线”“刷新就没了”“上线后打不开”等完整口语查询，不能只测标准组件名。

## 从旧词典迁移

1. 用版本快照固定原始文件，保留 212 个 ID，迁移以 `vibe-ui-dictionary/index.html` 为准。
2. 提取目录与提示词为数据文件，校验数量、ID、25 个分类与中英文内容，不运行旧补丁脚本。
3. 先迁移列表、搜索、详情、复制，再迁移首批 12 个演示；保留未迁移项的说明和旧版入口。
4. 为演示设置验证等级，逐条核对“提示词承诺”与“演示行为”，尤其是键盘、焦点、失败状态。
5. 完成对应验收后，才将新页面作为主要入口；历史源码仍可从 Git 找回。

## 演进触发条件

- 需要跨设备收藏/项目进度：先设计账号、数据权限和删除机制，再选择数据库及认证服务。
- 需要普通编辑人员浏览器内更新：评估 Git 驱动 CMS，复用内容模型，保留审核与版本历史。
- 搜索口语命中率不达标：先补别名和关联，再用同一查询集评估其他搜索方案；不直接以 AI 聊天替代搜索。
- 需要在线 AI 服务：单独设计服务端密钥、限额、费用和输入数据处理；模型密钥不得进入前端。
