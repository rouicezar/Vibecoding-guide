# 产品制作路线与板块覆盖

当前版本以以下路线为准，替代之前八节点、十节点方案。首页自身承载路线；另外十一板块全部有对应节点。板块映射不等于板块内容已经全部完成。

| 节点 | 核心产出 | 对应板块 |
| --- | --- | --- |
| 有一个想法 | 初步产品描述 | 项目分类 |
| 把想法告诉 AI | 开始对话 | 和 Agent 沟通 |
| 让 AI 提问补全 | 确认第一版范围 | 和 Agent 沟通、项目分类 |
| 让 AI 生成需求文档 | 功能、排除项、完成标准 | 和 Agent 沟通 |
| 让 AI 推荐技术选型 | 产品形式、技术组合、费用、限制与理由 | 项目分类、技术栈选择 |
| 让 AI 制定可跟踪的开发计划 | 任务编号、依赖、交付物、状态、验证记录 | 技术栈选择、和 Agent 沟通 |
| 让 AI 制作界面与组件 | 页面、交互、组件演示及描述话术 | 前端与 UI |
| 让 AI 接好数据与权限 | 数据保存、读取、权限验证；不需要后端则说明 | 后端 |
| 让 AI 按计划开发 | 目标平台上可运行且有版本记录的成果 | Web、手机 App、桌面 App 开发 |
| 让 AI 测试并修复 | 已验证项、问题及复查记录 | 测试 |
| 让 AI 协助部署上线 | 正式入口、发布检查与恢复方案 | 部署上线 |
| 让 AI 协助维护迭代 | 备份、费用、反馈与更新记录 | 运维 |

小程序属于项目分类内的路线，不增加一级板块。UI 组件词典属于界面节点的分支，沿用原 HTML 的“看到效果 → 知道名称 → 把描述交给 AI”的使用方式，迁移尚未完成。

## 依赖与回路

- 选型依据已确认需求；开发计划引用需求与选型。
- 界面、数据和平台实现都是计划中的任务，可按依赖交替推进，不要求先把全部界面与后端做完再开始开发。
- 完成状态分待开始、进行中、待验证、已完成。无验证记录不能冒充完成。
- 测试失败回到对应实现任务；需求变化回到文档并更新选型和计划；上线反馈启动下一轮。
- 账号验证、费用决定、真实体验确认仍由人工承担，AI 执行能力以实际工具权限为准。

## 视觉和措辞

蓝色表示想法与需求，紫色表示选型与计划，赭色表示制作，绿色表示验证与运行。编号、箭头和标题共同表达顺序，不依赖颜色识别。桌面四列蛇形连接，手机两列；连接线随尺寸重新计算。

面向使用者的中文文案禁用 U+4F60，采用动作、对象和结果表述；英文同步采用中性表达。范围包含导航、提示词、说明、弹窗及可访问性标签。原始历史素材不作为直接发布稿，迁移时执行同一规则。`npm run verify` 检查构建页面文案、板块映射和链接，避免后续回退。
