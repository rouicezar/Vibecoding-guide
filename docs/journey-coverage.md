## 连续实操入口（2026-09-23）

想法草稿 → `/tools/` 比较工具 → `/communicate/tools/` 验证项目访问 → `/communicate/setup/` Git与规则文件 → 回到第二节点交接想法 → 需求/设计/计划 → 环境 → UI风格/局部修改 → 完整流程/测试/试用/发布。每一步明确输入、操作、输出、检查与下一步；“比如”单独展示，通用模板不预填特定行业。跨模块的 `stage` 参数保留来源步骤。所有地址均有中英版本。

## 开发分支

- **页面与组件**：布局、交互、状态、组件词典。新增风格与局部修改实操；212词条已迁移，12个局部交互示例、200个演示仍待迁移。
- **数据与权限**：保存、读取、身份与访问边界。不需要保存或共享资料时可按选型记录跳过，不默认增加后端。
- **完整使用流程**：接通界面与数据，用测试资料从开始操作到结束，并在目标设备/平台验证。

分支按计划中的依赖交替推进，不强制先完成所有界面、再完成所有后端。原 `#stage-ui` 与 `#stage-backend` 地址保留，进入分支时主图选中开发节点。分支支持返回开发总览，语言切换保留当前位置。

## 条件路径与贯穿规则

- 已有可用 AI 工具时跳过注册准备，但核对能力与费用。聊天足够开展前期讨论；环境准备阶段核对文件读写和执行能力，不把聊天建议说成已执行。
- 小程序属于项目分类内路线，不新增一级板块。网站、小程序、手机及桌面 App 分别核对发布条件和设备验证要求。
- 每次改动保留可恢复版本；费用、账号验证、权限扩大与正式发布需要相应人工确认。
- 状态区分待开始、进行中、待验证、已完成、受阻；没有实际验证不能标记完成。
- 范围变化返回范围确认，再更新需求、选型和计划。
- 测试或验收失败回到对应开发任务，修复后复查；AI 测试不能替代人工验收。
- 上线反馈先区分故障与新需求。故障回到开发/测试；新需求回到范围确认。没有真实使用数据时不得虚构成效。

## 表达与可视化

全站发布中文禁用 U+4F60，英文采用中性动作表达。蓝色为想法/需求，紫色为选型/计划/环境，橙色为开发，绿色为测试/验收/上线/维护。图标、编号与箭头共同表达顺序；按实际容器宽度均衡分行：宽屏三行 4/5/4，较窄屏四行 4/3/3/3；每行两端对齐、间距与实际文字高度动态计算。窄屏为单列连续路线。距离不代表时间或 token 成本。选中节点无外圈。

模板保留具体示例、输入要求与输出约束。第一站是自行填写的草稿，第二站才附带 AI 沟通指令。构建验证覆盖文案、链接、模块映射、分支父级与关键节点顺序。

## 独立模块进度

沟通模块已开放 `/zh-cn/communicate/` 和 `/en/communicate/`，连接工具准备、提问、范围、需求、计划和环境节点。12个场景包含可填写完整模板与结果检查，覆盖单项修改、排查、恢复、验收和交接。后续技术栈、UI、后端、测试、上线和维护尚按分批推进；不以首页节点材料替代独立模块。

技术栈模块已开放双语 `/stacks/`，从选型、计划和环境节点可达，条件选择之后连接计划节点。工具能力与产品技术栈明确分开。

前端/UI独立模块已开放，首页页面分支可进入212项组件词典；详情连接沟通组件场景和完整使用流程。迁移原始词条不等于200项未迁移演示已完成；12个局部示例仅记录实际检查过的行为。

后端、测试、部署、运维独立模块已开放，首页所有板块映射现在均为可访问链接。共450个本地化地址（含212个词典详情的两种语言），原首页13节点/3分支保持不变。模块基础内容已实现；200项演示、平台实操、全文搜索与真人试用仍按任务记录管理。
