# 当前路线与统一表达

更新：2026-09-29。当前实现快照为 **6 个阶段、18 个节点、31 个动作**，不是教学标准或数量限制。目标与边界以 [产品需求](product-requirements.md) 为准。

## 术语与唯一来源

- 阶段：组织相关节点，共 6 个。名称由 `src/data/learning.ts` 的 `phases` 提供；`nodes.ts` 的 `nodePhases` 派生自它，不独立维护名称。
- 节点：主导航与独立页面单位，共 18 个。编号、名称、阶段归属及动作列表以 `src/data/nodes.ts` 的 `routeNodes` 为准。
- 动作：节点内具体执行内容，共 31 个，其中 27 个主线动作、3 个修复动作、1 个可选发布动作。页面内“步骤”表示本节点内的操作顺序，不另建全站编号。
- 资料：组件、术语、工具、专项方法和排障，为当前节点提供支持，不构成另一套制作路线。

## 最新六阶段

1. 把想法说清楚 / Define the idea
2. 准备协作空间 / Prepare the workspace
3. 把需求变成计划 / Turn needs into a plan
4. 制作并验证功能 / Build and verify
5. 验收与修复 / Accept and repair
6. 交付与持续维护 / Deliver and maintain

## 页面与兼容规则

首页、侧栏、路线图、搜索与资料返回入口采用同一套节点。`/node/<id>/#<action>` 是动作的直接入口。旧 `/learn/*`、`/roadmap/<旧节点>` 只负责兼容跳转，不渲染旧版教学页面或第二套路线图。静态托管使用即时 meta refresh，不能称为服务器 HTTP 301。

旧路线的排障材料迁入对应新节点的“更多问题与排障资料”。旧数据 ID 可作为兼容键保留，不得重新成为用户可见的旧导航。历史评审、规划和实施记录保留原始过程；与本页冲突时，以本页及当前实现为准。

## 当前学习体验

继续学习优先恢复主动进入的修复分支，否则前往首个未完成主线动作；可选发布不计入主线进度。节点页支持动作锚点、默认展开首个未完成主线动作、撤销核对，以及动作／节点／全路线进度反馈。核对失败会取消完成，存储失败会阻止完成后的跳转。

节点页页头下方给出「从这里开始」，直接指向本节点第一个未核对动作；若从侧栏跳步进入，会说明主线真正的下一个动作并给出入口。18 个节点全部可点，但跳步不再静默发生。侧栏、路线图与步骤卡片同时显示实际要亲手做的操作次数，不再只显示步骤数。

修复回路锁定进入它的那个节点：在 `live-check`、`package`、`release-review` 发现问题都留在本节点修，修完可一键回到本节点，不再统一弹回 `accept`。旧版只存步骤名的修复状态读取时自动补 `accept`，与旧版行为一致。

标为「不适用」的动作单独计数，显示为 `已完成数/总数（N 项不适用）`，不混入「已核对」——需要本人核对的动作从 11 个增加到 17 个，收录标准是失败时会不会静默（装错运行环境、打开错误目录、选错交付方式都不会报错）。未设门槛的 12 个动作全部是思考与整理类。

可选步骤（如 `publish`）独立成区，明确不计入节点进度、不符合条件可跳过，做完回到必做步骤；不再出现「0/1」与「共 2 个步骤 · 按顺序完成」同屏矛盾。

侧栏按阶段折叠，展开当前阶段；九槽位顺序和内容保留，辅助解释渐进展开。现有 86 个微操作均有双语预期结果与失败处理。755 个术语及已有参考资料按 18 个节点建立关联；节点级词表移到动手之前并默认折叠，关联说明何时查阅，不要求提前学完全部资料。

## 范围与验收

当前布局、UI 和逻辑结构固定，只在已有内容区细化操作、补充步骤说明和资料；动作数量不作为教学质量标准。本站提供步骤与方法，用户在所选工具中执行；不新增项目执行后台。内容核对、技术检查、实际跟做与学员试用分别记录，不能互相替代。

类型、构建、全部 13 条验证命令、Pages 子路径检查及代表性浏览器操作通过。实施范围和具体证据见 [学习体验实施记录](reviews/2026-09-29-learning-experience/实施记录.md)。整改提交 `cbedf9d`、`2abbf20` 已推送到 `main`，GitHub Pages 自动发布流程已触发；部署结果以 GitHub Actions 为准。
