# 12 个板块的页面布局与内容分层

状态：2026-09-23，依据用户最新澄清制定。本站由首页和 11 个独立内容板块组成；不再用四个合并栏目替代它们。本文件负责页面结构与呈现，[站点总规划](site-blueprint.md) 提供各主题的流程和提示词，[视觉规范](design-system.md) 管理共同样式。尚未开发页面。

## A. 固定的 12 板块与术语解释

专业名称与解释同时出现：**中文板块名 / 专业名称 → 一句普通人能理解的话 → 在本项目中解决什么问题**。专业词不再只藏在帮助页中，也不用英文替代中文。

| ID | 板块标题与专业名称 | 标题下直接展示的解释 | 规划主地址 |
| --- | --- | --- | --- |
| M01 | 首页 / Vibe Coding | 通过和 AI 说明需求、查看结果并不断调整，逐步做出软件的方法。 | `/` |
| M02 | 项目分类 / Project Types | 先决定做成网页、小程序，还是安装到手机或电脑里的应用。 | `/start/` |
| M03 | Web 站点开发 / Web Development | 制作一个别人用浏览器打开网址就能使用的产品。 | `/projects/web/` |
| M04 | 手机 App 开发 / Mobile App Development | 制作一个安装在手机上使用的应用。 | `/projects/mobile/` |
| M05 | 桌面 App 开发 / Desktop App Development | 制作一个安装在电脑上、可以处理电脑任务的应用。 | `/projects/desktop/` |
| M06 | 和 Agent 沟通 / Agent Communication | Agent 是能根据任务使用工具、执行多步工作的 AI 助手；这里教你把要求讲清楚并检查结果。 | `/communicate/` |
| M07 | 技术栈选择 / Tech Stack | 制作和运行一个产品所使用的一组技术与服务，相当于选择合适的搭建材料和工具。 | `/stacks/` |
| M08 | 前端与 UI / Frontend & User Interface | UI 是用户打开产品看到并操作的文字、图片、按钮及其排列；前端负责把这些界面和交互呈现出来。 | `/components/` |
| M09 | 后端 / Backend | 在界面背后处理资料保存、身份与访问规则等工作的部分。 | `/data/` |
| M10 | 测试 / Testing | 按具体步骤检查产品是否真的能用，以及出错时会发生什么。 | `/check/` |

小程序是 M02 下的项目类型，拥有 `/projects/mini-program/` 子路线，平台子页分微信、支付宝、抖音；它不是新增的第 13 个顶层板块。AI 工具比较 `/tools/` 是 M06 的辅助内容，术语 `/terms/`、搜索 `/search/` 是全站工具，排查 `/troubleshooting/` 由 M10 主归属、M12 引用。辅助地址可独立访问，不改变 12 个板块的数量。

## B. 全站布局

### 桌面页面框架

```text
┌──────────────────────────────────────────────────────────────┐
│ 品牌 / 回首页       全站搜索：我想找……              阅读帮助    │
├──────────────┬───────────────────────────────┬───────────────┤
│ 首页         │ 当前位置                       │ 本页目录      │
│ 项目分类     │ 中文标题 / 专业名称              │ 当前部分      │
│ Web 站点开发 │ 一句话解释 + 适合谁 + 能得到什么  │ 相关解释      │
│ 手机 App 开发│                               │               │
│ 桌面 App 开发│ 本板块内容                      │               │
│ 和 Agent 沟通│ · 入口 / 路线 / 示例 / 实操       │               │
│ 技术栈选择   │ · 完成判断 / 失败下一步           │               │
│ 前端与 UI    │                               │               │
│ 后端         │ 下一步 + 相邻板块入口             │               │
│ 测试         │                               │               │
│ 部署上线     │                               │               │
│ 运维         │                               │               │
└──────────────┴───────────────────────────────┴───────────────┘
```

左侧 12 项始终各自可点；可用分隔线分段，但不折叠成四个替代入口。顶栏不再重复放 12 个按钮。左侧标签使用中文及 UI、Web、Agent 等已有名称，完整英文与解释放在页头。当前项有背景、字重及位置标记，进入子页时保持所属板块高亮。

主内容视类型切换：概览和目录页不放右侧目录，给比较与预览足够宽度；长文与步骤详情才出现右侧目录。板块内分类放在主内容顶部，或在紧凑工具条中展开，不再堆第二条常驻左侧栏。

页面框架最大宽度 1440px；左导航 216px、右目录 176px、列间距 24px、外边距 24px；阅读正文最大 760px，目录内容可占用剩余宽度。主内容始终允许收缩。小于 1200px 不常驻右目录，小于 960px 主导航收为菜单，小于 640px 卡片改一列。手机页面顺序为顶栏 → 标题和解释 → 本板块目录/筛选 → 正文 → 下一步，所有功能不能依赖鼠标悬停。

### 导航有三个层次，职责分开

- 全站导航回答“我在学哪个板块”：左侧 12 项。
- 板块内目录回答“这个板块有哪些主题”：概览页的主题列表或卡片。
- 本页目录回答“这篇内容读到哪里”：详情右侧目录，手机折叠在正文上方。

进入深页用面包屑返回板块，例如“前端与 UI / 切换内容 / 标签页 Tabs”。不在每层重复一套巨型导航，不让用户通过连续弹窗找内容。

## C. 内容的四层

| 层级 | 用户的疑问 | 呈现方式 | 不该放什么 |
| --- | --- | --- | --- |
| L1 板块概览 | 这是什么？对我有什么用？从哪里开始？ | 标题、直接解释、一个简短例子、主要入口、完整主题目录 | 长篇理论、所有提示词、参数清单 |
| L2 主题或阶段 | 我现在要解决哪件事？ | 主题清单或路线阶段，每项一句用途、前提、得到的结果 | 同一屏展示全部细节与多个嵌套滚动区 |
| L3 具体行动 | 我要怎么做，怎样告诉 AI？ | 步骤、演示/对照、可复制话术、成功判断、失败去处 | 没有操作与结果的百科说明 |
| L4 深入解释 | 为什么这样？这个词与另一个有何区别？ | 按需展开的解释、关联术语、平台差异与官方来源 | 强迫新手先读完才允许执行 |

L1–L3 是前进路径；L4 是可随时取用的旁支，阅读后能返回原位置。成功条件、重要费用和会影响资料的决定不能藏在“了解更多”里。板块、主题与行动页有独立稳定地址；深入解释可用词条地址或展开区域的锚点定位。主要内容默认可见、可搜索，不把所有正文藏进标签页。

### 单篇行动页的固定顺序

1. 标题和术语：名称 + 一句话解释。
2. 这篇帮你完成什么：适合谁、开始前有什么、完成后得到什么。
3. 看一个例子：截图、对照、可操作演示或生活场景，选最能解释问题的一种。
4. 一步步做：每步写“你做什么 / 可以交给 AI 什么 / 看到什么结果”。
5. 可以这样告诉 AI：完整中文话术，必要输入先填写；英文版本为次级选项。
6. 检查是否做好：可观察结果与失败后的下一步。
7. 相关解释与继续：最多突出一个主下一步，另列少量相关入口。

同一页面的“阅读完成”“按步骤做过”“实际检查通过”分别标记。首期清单只作当前页面自查，不提供未经实现的跨设备进度。专业术语解释默认一行可见，进一步内容可点击、键盘展开；长解释进入词条页。

## D. 逐板块布局与内容

### M01 首页 / Vibe Coding

**首屏从上到下：**固定 Slogan“AI 时代，即使零基础不懂代码，也能 Vibe Coding。” → 一句方法解释 → 搜索 → 主按钮“从第一个网站开始”与次按钮“先看看项目分类”。不使用整屏营销图。

**下方内容：**11 个板块的完整目录，按原顺序呈现、用小图标和一句用途说明；接着是“我现在卡在……”四种问题快捷入口；最后是一个“说不清界面 → 找到 Tabs → 复制描述”的小示例。

**内容层级：**首页只做导览和示例，不承载全部教程。首次访问的主要下一步是 M02 或 M03，有经验的人通过全目录和搜索直接进入任一板块。

**每张目录卡字段：**中文标题、英文术语小字、一句用处、一个进入链接。11 卡首期不显示虚构热度、进度、完成时间或数量。

**验收：**用户能复述网站用途；不滚动到很远也能开始；完整目录包含所有 11 项而非只显示四类项目。

### M02 项目分类 / Project Types

**首屏：**术语解释 → “你想让别人在哪里使用？” → 网站、小程序、手机 App、桌面 App 四张比较卡。网站卡标“第一次做可从这里开始”，其他卡明确适合人群。

**卡片内容：**打开方式、适合场景、一个案例、准备条件、首版建议、进入路线。比较维度用“要安装吗 / 使用者在哪里 / 是否需要平台检查 / 常见准备”，不让新手比较技术参数。

**下方：**四类对照表 → 三问选择器（在哪里用、是否依赖设备能力、是否已有平台人群）→ “仍不知道怎么选”示例 → 对应路线入口。选择结果同时展示理由与适用边界，允许“暂不确定”。

**子内容：**四类说明、网站与 App 的区别、小程序平台选择、是否有必要同时做多个平台。小程序子路线再进入微信/支付宝/抖音的平台差异页，保留资料核验状态。

**术语示例：**Web“通过网址在浏览器打开”；Mini Program“小程序，依托现有平台打开”；Mobile/Desktop App“分别安装在手机/电脑上”。

**话术位置：**比较结果后提供“把我的选择告诉 AI”，包括使用人群、使用方式、第一版范围；不输出未经用户选择的多端需求。

**验收：**用户能选定一类并说出理由；小程序可继续走，不是只有名称的卡片。

### M03 Web 站点开发 / Web Development

**首屏：**解释、适合人群、作品展示站示例缩略图、完成后得到“一个别人能打开的网址”；主入口“开始第 1 步”，次入口“跳到我正在做的步骤”。

**主体布局：**上方阶段总览，下面是纵向编号列表。每项为步骤名、一句动作、准备项、得到的东西、进入按钮；不把九篇长文压进同一页面。

**阶段：**讲清用途 → 缩小第一版 → 选择制作方式 → 安排页面 → 先走通主要操作 → 补真实内容和手机显示 → 请人试 → 提供正式网址 → 上线后照看。

**阶段详情：**左侧仍是全站导航；正文显示“第几步”、本步产物、操作与话术、检查清单；底部上一阶段/下一阶段，右侧仅是本页目录。例子贯穿“个人作品站”，需要共享保存时再分到“活动报名页”。

**术语配解释：**Domain 域名“别人找到网站时输入的名字”；Responsive 响应式“在手机和电脑上自动调整排列”；MVP 最小可用产品“先能完成最重要一件事的第一版”。

**跨板块关系：**选方式引用 M07，安排页面引用 M08，保存资料引用 M09，检查/上线/维护引用 M10–M12，带着当前项目类型跳转并提供返回本步入口。

**验收：**每阶段都有可检查产物；学习路线不要求先认识框架或服务器。

### M04 手机 App 开发 / Mobile App Development

**首屏：**解释、适合已有网站经验的人、每日记录案例；Android/iPhone 选择、已有设备检查、主入口“先确认能在自己的手机上试用”。选择后 URL 保留条件，返回不丢失选择。

**主体布局：**设备准备条 → 路线步骤 → 手机特有问题卡 → 真实设备检查清单 → 发布入口。

**阶段：**为什么需要 App → 先选一种手机 → 安排使用过程 → 做最小版本 → 处理授权与断网 → 检查保存/换机 → 请人安装试 → 准备介绍 → 对应渠道开放 → 更新后复查。

**子主题：**相机/相册允许、通知、返回操作、离线、关闭重开、换机保存、试用与正式获取、旧版更新。平台差异显示在对应步骤旁，不同平台的发布流程不混排。

**术语配解释：**Permission 权限“允许应用使用相机等能力”；Offline 离线“没有网络时仍能做哪些事”；Beta 试用版“先交给少量人检查的版本”。

**示例形式：**手机框中的主要流程与拒绝授权后的结果对照；示意图不能标为真实安装记录。话术卡位于每个设备问题的解决步骤之后。

**验收：**读者知道先准备什么设备，能区分画面预览、真机试用、正式发布；所有选择有“我还不知道”的入口。

### M05 桌面 App 开发 / Desktop App Development

**首屏：**解释、Windows/Mac 选择、文件整理案例；说明第一版保留原文件、先处理副本。主入口“准备几个测试文件”。

**主体布局：**“输入文件 → 预览变化 → 确认 → 保存副本”四步示意 → 完整路线 → 常见电脑问题 → 安装/更新检查。

**阶段：**明确重复任务 → 选系统 → 排好操作顺序 → 样本试验 → 打开与保存 → 取消/关闭/失败 → 安装包 → 别人的电脑试 → 发布和更新。

**子主题：**选择文件夹、保存位置、重名、无法读取、处理中取消、关窗是否继续、安装与卸载、资料保留、版本更新。首期不默认开启监视用户文件夹或后台任务。

**术语配解释：**Installer 安装包“把软件放到电脑上使用的文件”；Local 本地“当前这台设备上的资料或操作”；File Permission 文件权限“软件是否被允许读取或改动指定文件”。

**示例形式：**文件列表整理前后并列；操作记录显示输入、目标和结果。话术默认要求测试副本、预览与确认；没有真实执行就不显示“已整理”。

**验收：**另一台没有制作工具的电脑能否安装与使用，是后续实操必须记录的结果，不能用开发者电脑截图替代。

### M06 和 Agent 沟通 / Agent Communication

**首屏：**Agent 的解释 → “你现在想让 AI 做什么？” → 场景选择；正文先出现一组“含糊表达 / 清楚表达”的对照。

**主体布局：**场景分类条 → 模板列表 → 一条选中模板的说明与可填写区域；宽屏填写在左、生成的完整话术在右，手机先填后看。初始结果标“示例”，不伪装成根据用户资料生成。

**12 个主题：**想法变第一版、先出方案、描述页面、描述组件、参考图片、单项修改、反馈问题、先排查、防止越改越乱、检查完成、新会话接手、上线前确认。

**每条模板：**适用场景、需要补的信息、为什么要这样说、示范、填写、完整预览、复制、结果检查。填写区最多先显示与本任务有关的必要字段，其他选项渐进展开。

**术语配解释：**Prompt 提示词“你交给 AI 的任务说明”；Context 上下文“AI 此刻拿到的背景材料”；Acceptance Criteria 验收标准“出现什么结果才算做好”。

**辅助内容：**AI 工具选择、如何给截图与资料、换会话如何交接。工具比较归在本板块，不与 M07 的搭建材料混淆。

**验收：**用户读得懂复制出去的每句话；缺关键资料要提醒；模板生成是本地整理，不假称模型诊断。

### M07 技术栈选择 / Tech Stack

**首屏：**技术栈解释与一张“AI 助手 / 产品搭建方式 / 发布位置”的关系图；先问“你准备做哪类产品”，不先展示一墙技术 Logo。

**主体布局：**需求问答 → 最多两个候选方案 → 选择理由/代价比较 → 常见方案目录 → 已有项目如何继续。

**问答字段：**产品类型、设备、保存与共享资料、是否登录、设备特有功能、预算、维护意愿；已有项目增加当前方案，不知道可留空。未核验的能力在结果中标未知，不默认满足。

**结果卡：**白话用途标题、实际技术名称、为什么适合、哪些情况不适合、费用类型、制作前要验证的部分、资料来源与日期、可复制选型说明。候选名保留但不要求用户理解每个组成部分后才能继续。

**子主题：**展示/内容站、经常操作的网页工具、带账号网站、手机、桌面、小程序、资料保存服务、继续已有项目。选型实例和当前本站的选型分开。

**术语配解释：**Framework 框架“已有的制作基础，帮你少从头搭一些部分”；Dependency 依赖“项目还需要用到的现成工具”；Hosting 托管“让服务商帮你放置或运行作品”。

**示例形式：**相同活动报名需求的两个方案，只比较用户关心的费用、资料和维护；不打未经验证的性能分数。

**验收：**读者能说出选择理由与代价；项目类型改变时结果跟着变化；不强推本站采用的 Astro。

### M08 前端与 UI / Frontend & User Interface

**首屏：**前端/UI 的区别和白话解释 → “描述你看到的样子”搜索 → “看整页布局 / 找一个组件”两个入口。搜索例子为“点一下下面有条线”，旁边展示可识别的小预览。

**主体布局：**目录工具条（分类、用途、结果数量）→ 组件预览网格 → 相似组件对比入口。分类在主内容内，不与全站导航混合。桌面两到三列，手机一列；列表只保留短摘要，完整提示词在详情。

**两条内容线：**页面布局讲上下/左右分区、导航、重点、空白和手机适配；组件词典完整保留 25 类 212 项，以日常用途聚合，原分类仍可筛选。

**组件详情顺序：**中文名 + 英文名 + 白话定义 → 适用场景 → 可交互演示与“已实现哪些行为”说明 → 可选变体 → 和相似组件的差别 → 填写文字/行为 → 复刻提示词 → 完成检查。演示与提示词并列仅在宽度足够时使用，窄屏按该顺序排列。

**术语配解释：**Component 组件“可反复使用的一块界面”；Layout 布局“各部分摆放的位置与大小”；Tabs 标签页“点不同标题切换不同内容”；Slider 滑块“拖动来调整一个数值”。

**示例：**Tabs 与 Slider 并排可操作，选错后能看见行为差异；颜色、文字、按钮状态采用本站设计 token，不随演示随机换风格。

**验收：**看图能找到名称，操作能理解行为，复制能给 AI 明确要求；部分演示必须明示范围，不靠“已保存”假提示证明真实保存。

### M09 后端 / Backend

**首屏：**术语解释 → “你的项目需要把什么记住？” → 三种情况（只展示 / 只存在自己设备 / 多人共享）及一个“是否需要后端”的说明入口。

**主体布局：**“填写 → 处理 → 保存 → 再次打开”的可视流程 → 按需求排列的功能主题 → 一条活动报名案例 → 检查资料与访问的清单。

**子主题：**保存、登录与找回、不同人能看什么、文件上传、连接外部服务、导出/删除、备份/恢复、费用与服务中断。每篇都回答数据在哪里、谁能用、失败怎么办。

**术语配解释：**Database 数据库“按规则保存和查找资料的地方”；Authentication 身份验证“确认你是谁”；Authorization 访问权限“确定你允许做什么”；API 接口“让两个软件按约定交换请求和结果的入口”。

**示例形式：**演示“报名人 / 组织者”两个视角，显示同一资料的可见差异。若仅为浏览器内模拟，必须标“权限示意”，不能声称已验证真实访问限制。

**话术位置：**读者选定资料、访问人群和保存需求后生成任务说明；输出包含实际保存与不同身份检查要求。

**验收：**读者知道页面显示成功和资料真正保存不同，也知道不需要给所有项目强加登录和后台。

### M10 测试 / Testing

**首屏：**解释 → “你想检查哪类产品？”与“现在已经能用，还是遇到问题？”；给一条“新增记录后关闭重开”的可见示例。

**主体布局：**主要任务填写 → 正常/意外/换设备/改后复查四组检查清单 → 问题记录器 → 排查卡目录 → 下一步。正常检查和故障排查共用板块，各有明确入口。

**子主题：**功能是否完成、信息为空或错误、重复操作、取消/断网、不同身份、手机与电脑显示、真实设备、修改后再检查、如何给 AI 有效证据。

**术语配解释：**Test Case 测试用例“一次具体操作及预期结果”；Bug 缺陷“实际表现和预期不一致的问题”；Regression Testing 回归测试“改完后把原来重要的操作再检查一遍”。

**检查项字段：**做什么、应该看到什么、实际结果、未检查/通过/不通过/不适用、截图或文字说明。本地勾选标为用户自查，不能宣称系统实际执行过。

**问题记录器：**页面/设备、操作顺序、期望、实际、最近变化；生成脱敏后的完整话术。首期不上传日志或截图到服务器。

**验收：**只检查了界面就不能显示资料保存已通过；清单项有失败去处，不能只有勾选动画。

### M11 部署上线 / Deployment & Release

**首屏：**解释 → 四种项目类型选择 → “自己能用 / 少量人试用 / 正式开放”三个阶段的区别。主入口“检查我还缺什么”。

**主体布局：**准备清单 → 所选类型的发布步骤 → 需要用户处理的账号/材料/费用 → 正式入口复查 → 失败时恢复办法。选择小程序/手机/电脑后进一步选平台或系统，保留上次页面带来的选择。

**子主题：**网站网址与托管、小程序平台检查、手机试用与发布、电脑安装包与来源、公开资料范围、费用、版本恢复。平台规则和操作日期在步骤旁可见。

**术语配解释：**Deployment 部署“把可运行的版本放到目标环境”；Release 发布“把这个版本交给目标用户使用”；Domain 域名“网站地址里便于记住的名称”；Rollback 回滚“退回之前的版本，资料是否恢复需要另查”。

**示例形式：**发布过程状态对照，明确“材料准备好”“提交检查”“获得通过”“正式可用”互不等同；网站和 App 不套用同一条状态链。

**话术位置：**清单后生成发布准备说明，含具体目标人群、目标入口、预算和验证；不在教程页面替用户执行发布。

**验收：**用户知道要拿到哪种入口、如何让别人验证；打包完成不能标为已上线。

### M12 运维 / Operations & Maintenance

**首屏：**解释 → “日常照看 / 准备更新 / 已经出问题”三个任务入口；读者可选择产品类型，不显示虚构运行状态和服务健康分数。

**主体布局：**任务入口 → 对应清单 → 费用与到期事项 → 备份恢复示例 → 维护记录模板。日常、更新、事故三种阅读路径共用真实案例与术语。

**子主题：**能否访问、功能检查、反馈、账单与到期、备份能否恢复、更新影响、暂停服务、退回旧版本、迁移和停止服务。出问题路径为“先确认影响 → 减少影响 → 收集现象 → 修正 → 复查”，关联 M10。

**术语配解释：**Monitoring 监测“持续留意是否还能正常工作”；Backup 备份“保留可用于恢复的资料副本”；Restore 恢复“用副本把需要的资料找回来”；Log 日志“软件工作和出错时留下的记录”。

**示例形式：**一张空的维护记录表加一条明确标“示例”的填写记录；展示“备份文件存在”和“已试过能恢复”的差别。

**话术位置：**每种任务末尾附完整说明，例如更新前后的检查计划；不默认给低频作品站生成复杂全天值守方案。

**验收：**能明确下次何时检查、遇到问题怎么处理，以及恢复页面版本不等于恢复全部资料。

## E. 内容卡片、术语与交互如何统一

| 内容形式 | 必须展示 | 展开/进入后展示 |
| --- | --- | --- |
| 板块入口 | 中文名、专业名、一句用处 | 概览、子主题、从哪里开始 |
| 主题条目 | 本次问题、适用项目、得到的结果 | 步骤、例子、话术、检查 |
| 路线步骤 | 编号、阶段名、产物 | 前提、行动、失败下一步 |
| 术语解释 | 标准名称、一句白话 | 生活/项目例子、边界、相关任务 |
| 组件条目 | 小预览、名称、行为、演示状态 | 完整演示、变体、提示词与对照 |
| 技术方案 | 用途、名称、适用条件 | 代价、限制、来源日期、选择话术 |
| 提示词 | 场景、全文或明确预览入口 | 填写、预览、复制反馈、验收方式 |
| 检查项 | 操作、预期、当前记录状态 | 实际结果、问题说明和下一步 |

术语第一次出现在正文时就解释，不要求跳走才看得懂。后续重复出现可用轻量词条链接。专业词不写成谐音或自创译名，也不将不同概念混为一谈。比喻之后说明边界，例如“数据库像资料柜，但还负责按规则查找和多人使用”。

版面精致依靠基线、行宽、间距和信息优先级。图标辅助识别，不承载唯一含义；标签每项只展示必要的项目类型、阶段或验证状态，避免一行彩色徽章。

## G. 内容模型与归属

模块注册表规划字段：id、order、titleZh、termEn、plainSummary、route、iconKey、overviewType、primaryAction、childTopics。恰好注册 M01–M12；辅助页不是模块。

内容项字段：id、primaryModuleId、relatedModuleIds、title、termRefs、plainSummary、level、projectTypes、platforms、stage、prerequisites、outcome、steps、promptRefs、successChecks、failureNext、relatedIds、sources、reviewedAt、status。按类型设必填项，不要求首页拥有教程步骤，也不要求纯定义具有独立复制表单。

primaryModuleId 决定面包屑与左导航，relatedModuleIds 只产生关联入口。术语用稳定 ID 集中维护同一解释，页面页头可使用同源摘要。共用步骤不复制到四条路线；引用跳转时传递项目类型，并显示“返回刚才的步骤”。

页面壳是共用的，主体有五种模板：导览首页、分类比较、项目路线、内容/方案目录、行动详情。不同板块选择合适模板，而不是每页换一套视觉系统。

## H. 开发前的布局与内容验收

1. 模块数量检查：首页 + 11 项，名称逐项对应用户清单；小程序、工具、术语和搜索没有意外升级成额外板块。
2. 内容层级检查：每项都能从概览进入主题，再到动作；深入解释可看可不看，不阻断主要步骤。
3. 术语检查：每个板块标题同时有专业名称与直接可见的解释；首屏没有未解释词堆砌。
4. 内容覆盖检查：逐板块写出第一屏、下方区域、子主题、示例形式、提示词位置、完成判断。
5. 导航检查：从任一详情可返回所属板块；跨板块引用保持项目条件，并提供返回原步骤。
6. 代表页面检查：已用 [五种文字线框](layout-wireframes.md) 明确首页、项目分类、Web 路线、UI 目录及 Tabs 详情的内容位置；后续用可操作原型验证共同页面壳，再进入完整视觉实现。
7. 真实验收边界：本文件和框图属于设计计划，不代表页面已构建、演示已运行或普通人已试用。
