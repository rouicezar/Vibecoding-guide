依赖图：需求与内容标准 → 基础工程 → 网站入门流程 → 按项目/平台组织的内容模型 → 组件词典迁移 / 沟通表单 / AI 工具与搭建方案选择 / 排查路径 → 全站搜索 → 真实新手试用 → 发布准备。

任务按纵向用户流程拆分，详见任务表。每个阶段保持站点可运行；内容齐全、构建通过、真实用户完成任务三者分别记录。

## 阶段检查点

1. 基础流程：网站入门步骤可从首页找到、读懂、复制话术并知道如何检查，类型检查和构建通过。
2. 核心工具：词典、模板和排查路径可完成代表性任务；交互及内容引用验证通过。
3. 内容完整：四条路线与前后端、检查、上线、照看专题达到基础内容审核标准，212 个词条无丢失，搜索通过口语查询集。
4. 用户验收：记录 5 位新手的真实试用，修复主要理解障碍；没有试用结果时保持待验收。
5. 发布：明确域名、平台、访问范围与公开内容，由用户授权后执行发布；未配置远程时不虚构 push。

## 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 写成术语百科，新手仍不会做 | 每篇必须绑定任务、话术、完成标志和失败分支 |
| 212 个演示迁移拖累整体 | 目录完整迁移，先校准 12 个，其他标明状态 |
| 中文搜索找不到生活化描述 | 先做固定口语查询集，再完善别名和权重 |
| 具体工具信息过时 | 标核验日期和来源，过期暂停推荐 |
| 首期被账号和 AI 聊天拖大 | 按已明确用户任务设触发条件，后续另立需求 |
| 框架选型纸面可行但运行有差异 | 早期用一个真实内容流程验证，再规模迁移 |
